# 共通ランタイムを触るときの注意

ここは**全ゲームの土台**。1行変えると過去のゲームが全部壊れうる。

## 変更したら必ず

```bash
npm run fun:all      # 全ゲームのゲートを回す（数字が変わっていないか見る）
```

数字が変わったら、それは既存のゲームの手触りが変わったということ。
意図した変更でないなら戻す。

前回の数字は `docs/records/gate/<slug>.json` に記録してあり、
**大きく動くと `npm run fun` が落ちる**（CI でも同じ）。意図した変更なら記録を更新する。

```bash
npm run fun -- <slug> --record    # いまの数字を新しい基準にする
```

記録の更新は「手触りを変えた」という宣言なので、**コミットに含めて理由を書く**こと。

## 変えてはいけないもの

| 対象 | 理由 |
|---|---|
| `VIRTUAL_W` / `VIRTUAL_H`（240×320） | 既存ゲームの座標が全部ずれる。レトロな見た目の根拠でもある |
| `FIXED_DT`（1/60） | 難度カーブが全部変わる。可変 dt にすると再現性が消える |
| `advance()` を通さない更新経路 | 実プレイとゲートで挙動が分かれると、ゲートの数字が意味を失う |

## 足すときの判断

**2本以上のゲームで実際に必要になってから**足す。
「あると便利そう」で足したものは、だいたい1本でしか使われず、読む量だけが増える。

例外は「全ゲームの体験を良くするもの」（リトライの速さ、惜しさの表示、共有）。
これは1本しか無くても入れてよい。ゲーム側の作業を減らす方向の投資だから。

## 依存を増やさない

外部ライブラリを入れない。物理エンジンも描画ライブラリも要らない。
15分で作るゲームに必要な計算は、四則演算と `Math.abs` / `Math.min` で足りる。
