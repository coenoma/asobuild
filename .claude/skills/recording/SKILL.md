# 収録する

この番組は**開発している画面そのもの**が本編。ターミナル・ゲーム画面・カンペを録って編集する。
だから「動くものを作る」だけでは終わらず、**作っている過程が見られる状態**になっている必要がある。

## いちばん大事なこと

**無言の時間が動画の敵。**

長い作業（ゲートを回す・ビルドする・調べる）に入る前に、カンペへ一言流す。
視聴者は画面しか見ていないので、**黙って考えている時間は「止まっている」と同じ**に見える。

```bash
npm run say -- "ボットが全滅した。判定が厳しすぎるかも"
```

これは**実装している側（多くの場合 AI）の仕事**。撮っている人はカメラの前にいて手が空いていない。

> 実測: この仕組みを作った直後、自動で流れるゲート結果は66件貯まったのに、
> 手で書いた一言は**2件**しかなく、しかも全部が最初の2分間のものだった。
> 「気が向いたら流す」に頼ると流れない。**作業の節目ごとに必ず流す。**

## 0. 画面の並べ方（この前提で作ってある）

録画は**横3分割**で撮る。カンペはこの縦長の列に置く前提でレイアウトしてある。

```
┌──────────┬──────────┬──────────┐
│ ターミナル   │  ゲーム    │  カンペ    │
│ (Claude Code)│ (ブラウザ)  │ (ブラウザ)  │
│          │          │ /live    │
└──────────┴──────────┴──────────┘
     1/3         1/3         1/3
```

カンペの窓は**画面の3分の1幅・縦いっぱい**にする。実測した想定サイズはこの2つ。

| 撮る画面 | カンペの窓 | 一言の文字 |
|---|---|---|
| MacBook Air 内蔵（1470×956 相当） | **約 490×880** ← 主対象 | 約 54px |
| フル HD の外部ディスプレイ | 約 640×1040 | 約 67px |

**横長のまま置かない。** 横長で開くと別のレイアウト（中央寄せ）になり、3分割に収まらない。

## 1. 立ち上げ

```bash
npm run dev:rec
```

普通の `npm run dev` との違い。

- カンペのログを空にしてから始める（前回の収録が混ざらない。**前回分は自動で `.bak` に退避される**）
- 立ち上がったらカンペ（http://localhost:3020/live）を自動で開く
- 撮る前のチェックリストを出す

画面隅の開発バッジは `next.config.ts` の `devIndicators: false` で消してある。

### 🔴 映り込み

**このリポジトリは PUBLIC。映ったものは公開されると思って扱う。**
他プロジェクトのウィンドウ・通知・ブックマーク・ターミナルの履歴に、
別案件の名前や秘密情報が出ていないか確認してから撮る。

## 2. 収録中に流すもの

| 何を | コマンド | いつ |
|---|---|---|
| **いま何をしているか** | `npm run say -- "文言"` | **節目ごと。これが主役** |
| その回の制約 | `npm run live -- constraint "ポテトMを食べ終わるまで"` | **撮り始めに1回。以降ずっと出る** |
| フェーズ | `npm run live -- phase じっそう` | きかく → じっそう → けんてい → ためし |
| 制限時間 | `npm run live -- timer start 12 "ポテトM"` | 制約を宣言したとき |
| 制限時間の終了 | `npm run live -- timer stop` | 早く終わったとき |

制約は**途中から見た人に何の回か伝える**ためのもの。時間を計らない回（1日・7日）でも出しておく。

**面白さゲート・雛形作成・遊んだ記録・公開前チェックは、コマンドを打てば自動で流れる**
（`npm run fun` / `npm run new` / `npm run playtest` / `npm run ship`）。
手で流すのは、その**あいだにある考えごと**のほう。

さらに `npm run fun` のたびに、**いまのゲームの見た目が1枚 `.live/shots/` に貯まる**（時刻つき）。
「白い四角 → 針と糸」のような見た目の変遷が、動画の素材として勝手に残る。
手で撮りたいときは `npm run snap -- <slug>`。

### 何を言えばいいか迷ったら

- 詰まったとき — 「ここで落ちてる。◯◯を疑ってる」
- 直す前 — 「判定を甘くしてみる」
- 数字が動いたとき — 「上振れが1.1倍しかない。運の要素が足りない」
- 見送る判断 — 「時間ないからここは切る」

**うまくいっていない時ほど流す。** 詰まっている過程がいちばん見られている。

## 3. 終わったら

```bash
npm run live -- archive
```

`docs/worklog/` に「何分に何が起きたか」の台本 md が出る。編集の目次になる。
**これを忘れるとログが次の収録で退避ファイル送りになる**ので、撮り終わったらすぐ実行する。

## 4. 出す前

```bash
npm run ship      # 型・ゲート・ビルド＋人が遊んだ記録
```

**時間切れで未完成のまま終わるのは動画として成功**だが、リポジトリに未完成のまま残さない。
撮影後に仕上げてから公開し、動画では「このあと直しました」と言う。

着想元があるゲームは、公開前に [権利の線引き](../../../docs/design/rights-and-originality.md) を通す。

## カンペの見方（何が出るか）

上から順に、縦に積んである。**優先順位は「一言 > 時間 > ゲート > ログ」。**

| 場所 | 中身 |
|---|---|
| いちばん上 | 番組名と、**その回の制約**（ずっと出る） |
| 帯 | フェーズ（きかく／じっそう／けんてい／ためし） |
| その下 | 制限時間のカウントダウン。**計測していないときは出ない** |
| **真ん中の特大文字** | **いまの一言**。出した直後は黄色く光る。長い文は3行で切る |
| その下の小さい字 | 一言が何分前のものか。**古くなると文字が薄くなる**（無言のサイン） |
| 枠 | 面白さゲート。**落ちた項目だけ**を出す（合格なら「12項目 ぜんぶ緑」だけ） |
| いちばん下 | 直近のできごと3件（時刻つき） |

**一言だけ読めれば成立する**ようにしてある。ゲートの詳細はターミナル側にも出ているので、
カンペでは「あと何項目か」と「何が落ちているか」に絞ってある。
