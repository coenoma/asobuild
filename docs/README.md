# ドキュメントの地図

**このファイルが、ドキュメントの置き場所の正。** 迷ったらここへ戻る。

書く前に決めることは1つだけ。

> **それは「ずっと効くもの」か、「1回ぶんのもの」か、「その日の時点のもの」か。**

この3つで置き場所が決まる。混ぜると、どれが今も効いているのか誰にも分からなくなる。

---

## 3つの層

### ① 永続 ── ずっと効くもの（原則・関所・資産）

**次に作る人（人でもAIでも）が、毎回読む場所。** 日付を名前に付けない。

| 場所 | 中身 |
|---|---|
| [design/](./design/) | 遊びの原則・型の地図・機種の地図・手触りのカタログ・権利の線引き |
| [video/](./video/) 直下 | 動画の原則・構成の型・テロップ・音・編集と公開の関所 |
| [research/](./research/) | 既存作の調査（**構造と数値だけ**。画は貼らない） |
| [guides/](./guides/) | 人間向けの手順（はじめかた・収録レギュレーション） |
| [decisions.md](./decisions.md) | 決めたことの索引（**中身は書かない。正へのリンクだけ**） |

### ② 回ごと・案件ごと ── 作り終えたら固まるもの

**1つ = 1ディレクトリ。** あとから「あの回どうしたっけ」を1か所で開けるようにする。

| 場所 | 中身 | 中のファイル |
|---|---|---|
| [episodes/](./episodes/) | **公開する動画1本ぶん**の成果物 | `script.md` / `storyboard.md` / `footage-notes.md` / `publish.md` / `thumbnail-prompt.md` |
| [plans/](./plans/) | **開発1件ぶん**の設計（4フェーズの成果物） | `design.md`（正）・必要なら `progress.md` |

### ③ 時点 ── 書いた日が意味を持つもの

**古くなること自体が情報。** だから消さないし、更新もしない。**新しく書き足す。**

| 場所 | 中身 |
|---|---|
| [video/research-notes/](./video/research-notes/) | 外部の調査・戦術を精査した記録（`YYYY-MM-DD-<題>.md`） |
| [records/](./records/) | 機械が書く記録（ゲート結果・遊んだ記録の JSON）。**手で編集しない** |

---

## 🔴 番号が2種類あることに注意

`plans/` と `episodes/` の番号は**別の体系**で、同じものを指していない。

| | 何の順か | 例 |
|---|---|---|
| `plans/NNN-slug` | **作った順**（ゲーム以外の開発も入る） | ぬいみちは `005-nuimichi` |
| `episodes/NNN-slug` | **公開する順**（動画の話数） | 同じぬいみちが `001-nuimichi` |

ぬいみちが plans では005、episodes では001なのはこのため。
**片方の番号でもう片方を探さない。** slug（`nuimichi`）が同じものを指す唯一の手がかり。

## ファイルの名前

| 層 | 付け方 | 例 |
|---|---|---|
| 永続 | 意味のある英語 slug。**日付を付けない** | `fun-doctrine.md` |
| 回・案件 | ディレクトリが `NNN-slug`、**中は役割の名前** | `episodes/001-nuimichi/script.md` |
| 時点 | **日付が先頭** | `2026-08-22-shorts-tactics.md` |

## 版を並べない

**`design.md` が常に正。** `design-v1.md` `design-v2.md` のように版を並べない。

- 前の版は git が持っている（`git log -p` で読める）
- 版が並ぶと「どれが今の正か」を毎回考えることになり、**必ず誰かが古いほうを読む**
- 大きく方針を変えたときは、**変えた理由を [decisions.md](./decisions.md) に1行**足す。それが履歴の入口になる

## 作り終わったらどうするか

| | 終わったあと |
|---|---|
| `plans/NNN-slug` | **`plans/archive/` へディレクトリごと移す**（消さない）。番号は変えない——**欠番が「終わった案件」の印**になる |
| `episodes/NNN-slug` | **そのまま残す。** 次の回が参照する資産（前回の素材メモ・公開文面の型） |
| `video/research-notes/` | **そのまま残す。** その時点の判断の根拠なので、古くなっても消さない |

> 他のリポジトリでは `plans/` が200件近くまで膨らんで、似た名前の案件が並んで探せなくなった実例がある。
> **終わったら移す**を最初から守る。

## 何を書かないか

- **コードを読めば分かること**（ディレクトリ構成・関数の一覧・依存パッケージ）
- **進行中の TODO・進捗**（CLAUDE.md に書かない。`plans/` の中でだけ扱う）
- **特定の実装の詳細を、永続の場所に**（すぐ腐る。原則に一般化できたときだけ `design/` へ上げる）

> Claude に守らせる規約は `docs/` ではなく [`.claude/rules/`](../.claude/rules/)、
> 手順は [`.claude/skills/`](../.claude/skills/)。**読者が違うので統合しない。**

## 遊んで出た指摘・調べた工夫の流れ

このリポジトリの中心にある仕組みなので、ここにも書いておく。

```
遊んで出た指摘（records/playtest）→ そのゲームを直す
    → 一般化できたら design/feel-catalog.md へ  ← ここが「次に必ず読まれる場所」
外部の調査 → video/research-notes/ で精査（採る／採らない／実測で決める）
    → 採ると決まったものだけ video/ 直下の関所へ昇格
```

**精査した時点では関所ではない。** 試して効いたものだけが昇格する。
