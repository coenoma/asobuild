# 見せる前提のゲーム設計

このリポジトリのゲームは、**遊べれば成功ではない**。

開発実況の動画で、**作っている途中も、完成後に遊んでいるところも、
初見の視聴者が見ていて面白い**ことを同じくらい重視する。

遊ぶ人向けの原則は [fun-doctrine.md](./fun-doctrine.md)。
ここは**遊んでいない人（見ている人）**向けの設計をまとめる。

> ## 「面白いゲーム」と「作るところを見て面白いゲーム」は別物
>
> ここを一緒にしない。**両方を満たすものだけを採用する。**
>
> | | 良い状態 | 誰が判定するか |
> |---|---|---|
> | 面白いゲーム | もう一回やりたくなる | 遊んだ人 |
> | **作るところを見て面白いゲーム** | **結果が気になる／失敗が絵になる** | **遊んでいない人** |
>
> たとえば「じっくり考えるパズル」は前者を満たしても後者を満たさない。
> 画面が動かず、成否が伝わらず、失敗しても何が起きたか分からないから。
>
> **企画を選ぶ段階でこの2つを別々に確認する。** 作ってから気づくと間に合わない。

---

## 1. 一目で状況が分かる

視聴者はコントローラーを持っていない。画面だけで、

- 今うまくいっているのか
- 危ないのか
- 失敗したのか
- 記録を更新したのか

が分かる必要がある。説明を読まないと面白さが分からないものは選ばない。

**作るときの判断**: 音を消して30秒眺めて、何が起きているか分かるか。分からなければ作り直す。

| やること | 具体 |
|---|---|
| 危険を色で固定する | 触れてはいけないものは常に同じ色（`bad`） |
| 残機を常時表示する | 減った瞬間が見えるように（●●● → ●●） |
| 失敗を画面全体で示す | 一瞬の赤フラッシュ＋ゆれ |
| 記録更新を明示する | 更新の瞬間に音と表示 |
| 見る場所を1つにする | 240×320は狭い。2箇所を同時に見せない |

## 2. 成否がハッキリする

「成功する？」「どこまで行ける？」「最高記録を超えられる？」——
**結果を見たくなる構造**が動画では強い。

進捗と結果が視覚的に伝わる指標を、必ず持たせる。

- スコア／距離／生存時間（どれか1つを主役に）
- コンボ・連続成功
- 残機
- 自己ベスト（常時表示）
- 称号（[fun-doctrine.md](./fun-doctrine.md) §2）

共通シェルがスコア・自己ベスト・称号を出すので、
ゲーム側は**主役の指標を1つ決めて、それを素直に増やす**だけでよい。

## 3. 失敗が面白い

完成品が完璧に動くことを目標にしない。動画では失敗のほうが強い。

- 盛大に落ちる
- ギリギリで失敗する
- キャラが変な動きをする
- バランスがおかしい
- 想定外の攻略法が見つかる

**バグをわざと入れる必要はない。** ただし
**失敗した瞬間が画面として分かりやすいゲーム**は優先度を上げる。

やられた瞬間の作り込みは [feel-catalog.md](./feel-catalog.md) F章。
（打ち上げてから、現実より遅く、回りながら落とす）

## 4. 完成後すぐ遊べる

「では遊んでみます」から、設定も説明もなしにプレイが始まる状態。

> タイトル → タップ → 数秒でプレイ

共通シェルがこのテンポを保証している。**ゲーム側でタイトル画面や説明画面を作らないこと。**

## 5. もう一回やりたくなる

動画後半で「いや、もう一回だけ！」となるものが相性がよい。

- 1プレイが短い（30秒〜2分）
- 再挑戦が1タップ・1秒以内
- 記録更新の余地がある

---

## 画面が動く頻度（ゲートで見ている）

見ている人にとって、**無風が続くと「何も起きていない」に見える**。

`npm run fun` の `画面で何かが起きる間隔` が、上手いプレイ中に
スコアが動く平均間隔を測っている（目安 0.25〜4秒に1回）。

- 長すぎる → 加点の刻みを細かくする、出てくる物を増やす
- 短すぎる → 何が起きたのか目で追えない。加点をまとめる

## 企画を評価するときの軸

ゲーム案を出すときは、**純粋な面白さだけで選ばない**。

> **「この条件で本当に作れる？」「AIに任せたら何ができる？」「できたゲーム、本当に面白い？」**

を見せるのが企画の中身。だから案には次を必ず添える。

1. **権利面での注意点** — 着想元があるなら、何を借りて何を自作するか（[rights-and-originality.md](./rights-and-originality.md)）
2. **動画で最も映える瞬間** — どこが切り抜きになるか
3. **視聴者が結果を見たくなるポイント** — 何が「見届けたい」を作るか
4. **成功／失敗の見えやすさ** — 遊んでいない人に伝わるか

**作る過程を見せると面白いゲームを作ることは、ゲームを作ることと同じくらい重要。**
