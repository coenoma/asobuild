# 面白さの原則

企画ごとに考え直さない部分をここに固定する。
**毎回考えるのは「何を作るか」だけで、「どう面白くするか」は毎回同じ手順を踏む**ための文書。

> ここに書いてあるのは主に **action（反射・タイミング）** を念頭にした原則。
> パズル・育てる・引き・1回きり、で変わる部分は [genre-map.md](./genre-map.md) を先に読むこと。
>
> ここは**遊ぶ人**にとっての面白さ。
> **遊んでいない人（動画で見ている人）**にとって面白いかは [broadcast-design.md](./broadcast-design.md)。
> このリポジトリでは両方が同じくらい重要で、片方だけ満たしても採用しない。

---

## 0. 規模の決まりごと（企画によらず、ここは毎回同じ）

### 制作時間は企画ごとに変わる。作るものの規模は変えない

制作時間（コーヒー1杯／ポテトM1個／30分／1時間／1日／7日）は**動画の企画**であって、品質基準ではない。
一方で、**作るものの規模は毎回同じ**にする。

| | 決まり |
|---|---|
| 1プレイ | 30秒〜2分で終わる |
| ひととおり | **一気に遊んで15〜30分でやりきれる** |
| 制作時間 | 企画による（毎回変わる） |

### 時間が余ったら、広げるのではなく濃くする

これがいちばん間違えやすいところ。7日もらったからといって、100ステージ作らない。

- ❌ ステージを増やす／モードを増やす／要素を足す
- ⭕️ 同じ規模のまま、手触り・演出・判定・目標の刻み・見た目の密度を上げる

**大きいものは、作りきれないし、遊びきれない。**
15〜30分で遊びきれる範囲に、ハマる要素・次にやりたくなる要素・やりきり感・人に言いたくなる要素を**凝縮**する。それがこのリポジトリの作るものの定義。

ステージ制のものを作るときも同じ。10〜15面で「ぜんぶ終わった」まで行く構成にする。

## 1. 1プレイの原則（七つ）

### ① 入力は1つ
押す／押さない、それだけ。位置を狙わせるのも例外的な場合に限る。
操作説明が2行必要になった時点で、この企画には向いていない。

> 実装: `meta.control` は `tap` / `hold` / `tap-hold` / `aim` の4つだけ。増やさない。

### ② 3秒で最初の1点、10秒で最初の失敗
初見の人が3秒で「こうすればいいのか」と分かり、10秒以内に1回失敗する。
この2つが揃うと、人は必ずもう一回やる。「最初の1点が遠い」ゲームは二度と開かれない。

> ゲート: `初見でも点が入る` / `理不尽な即死がない`

### ③ 緊張の軸は1つだけ、時間とともに上げる
速くなる、詰まってくる、減っていく。どれか1つ。
2つ以上を同時に上げると、何が原因で負けたか分からなくなり、上達感が消える。

> ゲート: `放置すると死ぬ` / `上手くてもいつか終わる`

### ④ 死んだ理由が0.5秒で分かり、死ぬところが見て楽しい
何が来るかは事前に見えていて、回避手段があり、失敗したら理由が出る。
「なんで死んだか分からない」は、そのまま離脱になる。

そのうえで、**やられる瞬間の絵に手をかける**。
何年も経って語られるのは、たいてい「あの落ち方」のような失敗の絵のほうで、得点の仕組みではない。
失敗が見て楽しいと、失敗が罰でなくなり、何度でも押せる。

> 実装: `reason()` を必ず書く。やられた絵は `launchTumble()`（[feel-catalog.md](./feel-catalog.md) F章）。
> やられた後も 0.85 秒間 `step` が回るので、そこで演出だけを進める。

### ⑤ もう一回までの摩擦をゼロにする
リザルトからリトライまで1タップ・1秒以内。確認も広告も遷移演出も挟まない。
共通シェルが保証しているので、**ゲーム側でリトライ画面を作らないこと**。

### ⑥ 惜しさを見せる
自己ベストは常に画面に出す。近づいたら色を変える。終わったら「あと◯点」を出す。
人が繰り返すのは「勝ったから」ではなく「あと少しだったから」。

### ⑦ 上振れを作る
毎回だいたい同じ点で終わるゲームは3回で飽きる。
「今日は乗ってる」が起きるように、リスクを取れる選択肢か、連続成功のボーナスを1つ入れる。

> ゲート: `上振れがある`（スコアの p90 が中央値の1.3倍以上）

## 2. ひととおり遊びきるための原則（やりきり感）

1プレイが面白いだけでは、15〜30分もたない。**段階的な到達目標**を必ず入れる。

### 称号を3〜5段階置く

```ts
goals: [
  { score: 100, label: '主任' },   // 1〜2プレイで届く
  { score: 300, label: '係長' },
  { score: 700, label: '課長' },
  { score: 1300, label: '部長' },  // 一気に遊んで15〜30分で届く
]
```

- **最初のひとつは1〜2プレイで届く**線に置く。最初のごほうびが遅いと2回目が起きない
- **最後のひとつは、一気に遊んで15〜30分**で届く線に置く。ここが1セッションの長さを決める
- 名前は世界観に合わせる（出世・段位・階級・進化）。数字より人に伝わる

共通シェルが、称号の獲得演出・現在の称号・「次は◯◯まであと△点」・全達成表示・
称号入りの共有文まで全部やる。**ゲーム側は `meta.goals` を書くだけ**。

> ゲート: `最初の称号がすぐ届く` / `一気に遊びきれる長さ`
> 後者は、上手いボットが最後の称号に到達するまでの想定時間を実測して判定している。

### やりきったあとに何を残すか

- 全部埋めた事実（タイトル画面に「ぜんぶ達成ずみ」が出る）
- 人に言える形（称号入りの共有文が1タップで出る）
- 数字ではなく肩書きで語れること（「部長までいった」は人に言いやすい）

## 3. 一段上に行くための1つ：「押さない」を選ばせる

原則を全部満たしても、まだ「ただの反射ゲーム」で終わることがある。
そこから一段上げる最短の手は、**押してはいけないものを混ぜる**こと。

- 押す＝得点、押さない＝ゼロ、だとプレイヤーは考えなくていい
- 押すと損をするものが混ざった瞬間、「見る」「待つ」「見送る」が生まれる
- 待った結果うまくいったときの快感は、反射で当てたときより強い

見本の `hanko`（ハンコ課長）では「赤い差戻」がそれ。
連打では勝てず、見送る判断が要り、それでもルールは一行で説明できる。

## 4. やらないこと

| やらない | 理由 |
|---|---|
| チュートリアル画面 | 説明が要る時点で①に反している |
| 設定・難易度選択 | 選ばせると迷う。難度は時間で上げる |
| ログイン・サーバ保存 | 記録は端末内で足りる。持たない分だけ速く作れる |
| 5秒を超える演出 | もう一回までの摩擦になる |
| 100面・複数モード・成長要素 | 15〜30分で遊びきれなくなる（§0） |
| 既存ゲームのコピー | 真似ていいのは当時の「文法」まで（下記） |
| 実在の企業ロゴ・商品名の再現 | 制約として「マックのポテト」を撮るのはよいが、ゲーム内に商標を持ち込まない |

### 「既存のコピーを作らない」の線引き

- ❌ 有名タイトルの見た目・名前・面白さの中心をそのまま持ってくる
- ⭕️ 当時のジャンルが共有していた**文法**（1ボタン、スコアアタック、単調な加速）を使う

文法は誰のものでもない。真似るのは文法までにする。

## 5. 面白さゲートとの対応

`npm run fun -- <slug>` が見ているのは、上の原則が実装に入っているかどうか。

| ゲート項目 | 対応 |
|---|---|
| 再現性 | 技術要件（乱数は `rng` 経由で） |
| 放置すると死ぬ | ③ 緊張の軸 |
| 初見でも点が入る | ② 3秒で1点 |
| 理不尽な即死がない | ② 10秒で最初の失敗 |
| 連打だけでは勝てない | §3 押さない選択 |
| 腕前が効く | ③ 上達感 |
| 上手ければ続く | ③ 伸びしろ |
| 上手くてもいつか終わる | ⑤ もう一回 |
| 上振れがある | ⑦ 上振れ |
| 最初の称号がすぐ届く | §2 最初のごほうび |
| 一気に遊びきれる長さ | §0 規模・§2 やりきり感 |

**ゲートは合格ラインであって、目標ではない。** 全部緑でも、実際に遊んで「もう一回」と思わなければ面白くない。
最後の判定は必ず人がやる。ゲートは、人が判定する価値もない状態を弾くためにある。

> ⚠️ **一度これで失敗している。**
> たまごポン初版は全項目を通ったが、遊ぶと「何をすればいいか画面から分からない」ゲームだった。
> ゲートが見ているのは**数字に出る性質**だけで、「操作の意味が伝わるか」「上手くなる余地があるか」は見ていない。
>
> そこで `npm run playtest` で**人が遊んだ記録**を残すようにした。
> 記録には実装の指紋が入るので、直したら遊び直すまで `npm run ship` が通らない。
> 経緯: [../plans/002-tamago-remake/design.md](../plans/002-tamago-remake/design.md)

## 6. 数字の目安

迷ったときの初期値。ここから触る。

| 項目 | 目安 |
|---|---|
| 1プレイ（上手い人） | 40〜90秒 |
| 1プレイ（初見） | 10〜20秒 |
| 最初の1点まで | 3秒以内 |
| 判定の甘さ | 「ちょっと甘いかな」で正解（辛いと初見が帰る） |
| 難度が上がりきるまで | 45〜60秒 |
| ライフ | 3（1ミスで終わると理不尽、5以上だと緊張しない） |
| 称号の数 | 3〜5個 |
| ひととおり遊びきる時間 | 15〜30分（ゲートが実測して判定する） |

作り方の具体は [retro-style.md](./retro-style.md)、進め方は [../guides/はじめかた.md](../guides/はじめかた.md)。
