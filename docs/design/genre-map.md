# 遊びの型の地図

当時のケータイゲームを、**作り方が変わる単位**で5つに分けたもの。

なぜ分けるかというと、**型が違うと「良い状態」が正反対になる**から。
反射ゲームでは「放置すると死ぬ」ことが必須だが、育成ものでは逆に
「放置しても壊れない」ことが必須になる。同じものさしを当てると、
正しく作れているものが不合格になる。

`meta.genre` に型を書くと、面白さゲートが見る項目が切り替わる。

> 型と**機種**（`meta.platform`: ケータイ／PCブラウザ／ゲーセン）は直交する。
> 型が「面白さの検査」を決め、機種が「画面の寸法・向き・入力」を決める。
> 機種の選び方は [platforms.md](./platforms.md)。

---

## 当時の実際の分布

参考にしたガラケー名作7選では、**7つ中4つが「タップして上昇する」系統**だった
（糸通し／チャリ走／Papi Jump／SFCave、加えて「おばちゃんが跳ぶ」も同系）。
残りは大富豪＋不動産のシミュレーション、ビーチバレーなど。
[出典: モバレコ](https://mobareco.jp/a54453/)

一方で市場全体を見ると、テキストアドベンチャーと育成から始まり（1999-2003）、
Java対応でアクション・RPG・シミュレーションに広がり（2004-2006）、
釣り★スタ以降は収集・カードバトルへ移った。
[出典: 日本モバイルゲーム産業史](https://news.denfaminicogamer.jp/japan-mobile-game-history) /
[携帯電話ゲーム - Wikipedia](https://ja.wikipedia.org/wiki/%E6%90%BA%E5%B8%AF%E9%9B%BB%E8%A9%B1%E3%82%B2%E3%83%BC%E3%83%A0)

つまり**反射系は主流のど真ん中だが、それだけではない**。この地図はその差を埋めるためにある。

## ① action — 反射・回避・タイミング

**当時の例**: 糸通し、チャリ走、Papi Jump、SFCave、おばちゃんが跳ぶ

| | |
|---|---|
| 遊びの構造 | 時間が進み続け、正しい瞬間に押す／押さない |
| 面白さの源泉 | 反射と予測。上達がそのまま記録になる |
| 終わり方 | 失敗の蓄積で死ぬ |
| 1プレイ | 30秒〜2分 |
| ゲートで見るもの | 放置すると死ぬ／理不尽な即死がない／連打では勝てない／上手ければ続く／いつか終わる |
| 動画映え | ◎ 危ない瞬間と失敗が一目で分かる |
| 勘所 | 緊張の軸は1つ。時間とともに上げる。押してはいけないものを混ぜる |

## ② puzzle — 手を選ぶ

**当時の例**: 落ちもの、ソリティア、数独、詰めもの

| | |
|---|---|
| 遊びの構造 | 盤面があり、時間ではなく**手番**で進む。考える時間がある |
| 面白さの源泉 | 「いま何を選ぶか」。読みが当たる快感 |
| 終わり方 | 手詰まり、または盤面を片付けて完了 |
| 1プレイ | 1〜5分 |
| ゲートで見るもの | でたらめでは勝てない／上手ければ続く／いつか終わる／上振れ |
| 動画映え | ○ 盤面が見えるので状況は伝わる。ただし考える時間が「無風」に見えやすい |
| 勘所 | 手詰まりを早く来させない。最善手が一意にならないようにする（選択の幅） |

> ⚠️ 考えている間は画面が止まる。**盤面の予告（次に来るもの）を常に見せる**と、
> 見ている人にも「次どうするか」が伝わる。

## ③ nurture — 育てる

**当時の例**: たまごっち系（ぎゃおッPi など）、農園ホッコリーナ

| | |
|---|---|
| 遊びの構造 | 時間が進み、状態が少しずつ変わる。**放置そのものが遊びの一部** |
| 面白さの源泉 | 手をかけた分だけ結果が変わる。どう育つかの分岐 |
| 終わり方 | 一定時間で結末（成長しきる／だめになる） |
| 1プレイ | 2〜5分（**当時のような数日単位にはしない**） |
| ゲートで見るもの | **放置しても壊れない**／世話が効く／いつか終わる／上振れ |
| 動画映え | △ 待ち時間が出るので、変化を目に見える形にする必要がある |
| 勘所 | 見ていない時間があるのが前提。減るものは減っても取り返しがつく形に |

> ⚠️ **action と要求が正反対**。放置で即死するとゲートに落ちる。
> 逆に、世話をしてもしなくても同じ結果なら「腕前が効く」で落ちる。

## ④ chance — 引き・収集

**当時の例**: 釣り★スタ、カードコレクション系

| | |
|---|---|
| 遊びの構造 | 一回の行為（引く・釣る・開ける）と、その結果の蓄積 |
| 面白さの源泉 | 運の波。ときどき来る大当たり |
| 終わり方 | 回数切れ、または目標到達 |
| 1プレイ | 30秒〜2分 |
| ゲートで見るもの | 上振れ（強めに要求）／それでも判断が効く／いつか終わる |
| 動画映え | ◎ 「引く瞬間」が最高に映える |
| 勘所 | 運だけにしない。**引く前に選ぶ余地**（どこで釣るか、いつ引くか）を必ず置く |

## ⑤ oneshot — 1回たどり着いて終わり

**当時の例**: 脱出ゲーム、診断、クイズ、テキストもの

| | |
|---|---|
| 遊びの構造 | 一本道またはツリー。解けたら終わり |
| 面白さの源泉 | 分かった瞬間。結果を人に言いたくなること |
| 終わり方 | クリア（繰り返さない） |
| 1プレイ | 3〜15分 |
| ゲートで見るもの | 最後までたどり着けるか／初見でも進めるか／画面が動くか |
| 動画映え | ◎ 詰まる→ひらめく、の落差が強い |
| 勘所 | リプレイ性がないぶん、**1回の体験を濃く**。共有できる結果を必ず出す |

> 繰り返し前提の項目（放置で死ぬ・上振れ・連打）はすべて外れる。
> 代わりに「詰まらないか」「ちゃんと終われるか」を見る。

## 扱わないもの（意図的に）

| 対象外 | 理由 |
|---|---|
| 長編RPG・長編アドベンチャー | 15〜30分で遊びきれない。短時間で作れもしない |
| 対人対戦・オンライン | サーバーを持たない方針と噛み合わない（**CPU相手はこれに当たらない**。下記） |
| 数日〜数週間かけて育てるもの | 1セッションで完結しない。動画にならない |
| ガチャ課金を模したもの | 番組の趣旨と合わない |

RPGを「やりたい」と思ったときは、**RPGの何が面白いのかを1つだけ取り出して、
30秒で味わえる形にできないか**を考える。それが上の5つのどれかに収まるなら作れる。

### CPU相手の勝負は扱ってよい

「対人対戦」を外している理由は**サーバーを持たないから**であって、
勝負という形そのものを禁じているわけではない。CPU相手なら端末の中で完結するので、
この方針とぶつからない。

サイコロを振って進む、資産を競う、といった**盤の上の勝負**は、
`chance`（引きが主役）か `puzzle`（手を選ぶのが主役）に収まる。
どちらかは「何をしている時間がいちばん長いか」で選ぶ。

---

## ⚠️ ターン数で終わるゲームは、ゲートの足切りが弱くなる

「時間切れで死ぬ」のではなく「**決めたターン数を使い切って終わる**」ゲームでは、
生存時間で見る項目（上手ければ続く／上手くてもいつか終わる／連打では勝てない／放置すると死ぬ）が、
**でたらめボットでも自動的に通ってしまう**。上手い人も下手な人も同じターン数で終わるからで、
これはゲームの出来を何も見ていない。

実際に効くのは次の5つだけになる。

- 腕前が効く（運ゲーでない）
- 上振れがある
- 画面で何かが起きる間隔
- 最初の称号がすぐ届く
- 一気に遊びきれる長さ

**足切りが弱いぶん、`npm run playtest` の重みが増す。**
緑になっても「ほとんど何も見ていない緑かもしれない」と考えること。

もうひとつ、**1プレイの長さがボットと人でずれる**。
ボットは即決するので数十秒で終わるが、人は考えるぶん何倍もかかる。
`一気に遊びきれる長さ` はボット基準の推定値なので、ここは人が遊んで確かめるしかない。

## 型の選び方

1. **何をしている時間がいちばん長いか**で選ぶ（避けている／考えている／世話している／引いている／探している）
2. 迷ったら `action`。当時の主流であり、いちばん短く作れて、いちばん動画映えする
3. 型をまたぐ案（例: 育てながら反射でよける）は、**主になる方**を選ぶ。両方は満たせない

型を書き間違えると、ゲートが見当違いの判定をする。`npm run fun` の見出しに型が出るので、
毎回そこを確認すること。

---

## 型が増えるとき

新しい型を足すのは、**既存の5つのどれでも説明できない遊びが2本以上出てきたとき**。
1本のために型を足すと、ゲートの分岐だけが増えて誰も使わない。

足すときは `Genre` 型 → `GENRE_GATE` → `GENRE_CHECKS` → この地図、の順で必ず4点セットで更新する。
