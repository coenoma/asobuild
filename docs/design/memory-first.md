# 記憶から作る

**既存の有名ゲームを題材にするときの、このリポジトリのやり方。**

> 本物を見ながら細かく写させるのではなく、
> **自分の記憶だけをAIに渡して、どこまで再現できるかを見る。**

これは権利対策として仕方なくやっていることではない。
**企画としてこちらのほうが面白く、結果としていちばん安全**でもある、という順番。

線引きの本体は [rights-and-originality.md](./rights-and-originality.md)、
調べ方は [../research/README.md](../research/README.md)。

---

## 1. なぜ記憶からなのか

### 企画として面白い

本物を見せてコピーさせると、**答え合わせの動画**になる。似ているかどうかしか残らない。

記憶から作ると、こうなる。

```
本人の記憶  →  言葉にしてAIへ渡す  →  AIが解釈する
        →  なんかそれっぽいものが出てくる  →  遊ぶ
        →  「そうそう、これこれ」／「いや、全然違う（笑）」
```

**この最後の一行が中身。** 記憶と出てきたものの差そのものが見どころになる。
視聴者も自分の記憶と照らし合わせるので、当時を知っている人ほど強く反応する。

### 結果としていちばん安全

コピー元の画面を見ないので、**具体的な表現が混入する経路がそもそも無い**。
「気をつけて作る」より「見ない」ほうが確実に守れる。

## 2. 何を渡してよくて、何を見ないか

| AIに渡してよい | 見ない・渡さない |
|---|---|
| 自分の記憶（言葉で書いたもの） | 元作品の画面・スクリーンショット |
| 当時の**感想・レビューの文章** | 元作品の映像・実況動画 |
| 遊びの仕組み（自動で進む／1ボタン／距離を競う） | 元作品のアセット・音・コード |
| 「なぜ流行ったか」の分析（数値・構造） | 元作品のUI配置・配色・キャラの形 |

**当時の感想を読むのは、むしろ推奨。** 何が良くて何が不満だったかは文章で残っていて、
それは表現のコピーではなく**評価の情報**だから。

> 実例（ぬいみち回）: 渡したのは「押している間だけ上がって、離すと落ちる。
> 上がる速さと落ちる速さが同じくらいでゆっくり」という記憶と、
> 当時の感想2つ（「判定がシビアすぎる」「単調で飽きる」）だけ。画は1枚も見せていない。

## 3. 手順

1. **お題を決める**（「あのゲーム、覚えてる？」で始まるもの）
2. **記憶を言葉にする。** 見ないで書く。曖昧なところは曖昧なまま書く
   - 「たしか自動で進んで」「タップで上がって」「音は……覚えてない」
   - **曖昧さは弱点ではない。** そこにAIの解釈が入る余地ができて、ズレが生まれる
3. **当時の感想を集める**（テキストのみ）。とくに**不満**を探す
   - 不満は「そこを直せば今でも面白くなる」場所そのもの
4. **記憶＋感想だけをAIに渡す**
5. **出てきたものを遊ぶ**。記憶とどこが違うかを口に出す
6. **面白さの肝を、不満のあった方向へずらす**（[fun-doctrine.md](./fun-doctrine.md)）

### 「調べてから作る」との関係

[research-classic スキル](../../.claude/skills/research-classic/SKILL.md) は
「作る前に調査を通せ」と言っていて、一見ぶつかる。ぶつからない。

- **調べるのは「なぜ流行ったか」**（判定の甘さ・演出のタイミング・目標の刻み）。**構造と数値**
- **見ないのは「どう見えたか」**（絵・UI・キャラ・配色）。**表現**

調査は `docs/research/` に**言葉と数値で**残す。そこに画像を貼らない。
そうしておけば、次に作るときも安全に読み返せる。

## 4. このリポジトリが作るものは2方向ある

**どちらも同じくらい大事。** 片方に寄せない。

### ① 再現の実験 ── 「AIだけで、あれを作れる？」

有名なゲームをお題にして、記憶からどこまで行けるかを試す。
入口が広く、当時を知っている人に一発で届く。

### ② 架空の新作 ── 「2006年にあったら流行ったんじゃない？」

当時のゲームデザインの文法だけを抽出して、**存在しなかった新作**を作る。

- 1ボタン／スコアアタック／意味不明なくらい単純
- ちょっと変な題材（ハンコ、傘、社員証）
- ガラケーの画面でも成立する簡素さ
- 口コミで学校中に広まりそう

**単に「昔っぽい見た目」にするのではない。**
「なぜあれは単純なのにハマったのか」をゲームデザインとして分解し、**その原理から新しく作る**。

②は権利の心配がほぼ無く、しかも「当時こんなのあったかも」という感覚は①と同じくらい強い。
①で貯めた分析（[feel-catalog.md](./feel-catalog.md)）が、そのまま②の材料になる。

## 5. 動画にするとき

企画の型は「**記憶だけで、あれを作れるか**」。
[video-doctrine.md](../video/video-doctrine.md) §0 の「実験の記録」と同じ形になる。

- 冒頭で**記憶を声に出す**。「自動で進んで、タップで跳んで……だったと思う」
- 出てきたものを見て**素で反応する**。「そうそうこれ」「いや違う」
- **元作品の名前はタイトル・概要欄・テロップに書かない**
  （[safety-checklist.md](../video/safety-checklist.md) §3）
- 調べているときの画面（検索結果・ストア・SNS）は**映さない**。
  自作の図解とターミナルのテキストに差し替える

**「見た瞬間にあれそのもの」ではなく、「遊んだら、うわーこの感じ懐かしい」を狙う。**
