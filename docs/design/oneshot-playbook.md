# oneshot の作り方 ── 診断・クイズ・判定ものの設計文法

`oneshot`（1回たどり着いて終わり）は、心理診断・クイズ・恋愛二択・日常判定・雑学の**ほぼ全部が落ちる型**。
なのに**既存4本は全部 action で、oneshot はまだ1本も作られていない**。
[genre-map.md](./genre-map.md) は型の地図、ここは**実装レベルの文法**。oneshot を作る前に必ず読む。

---

## action と何が違うか（頭を切り替える）

| | action | oneshot |
|---|---|---|
| 時間 | 進み続ける。放置すると死ぬ | **止まっている**。入力を待つ |
| 1プレイ | 30秒〜2分 | 1〜5分（診断3問なら1分） |
| 終わり方 | 死ぬ | 最後の画面に**たどり着く** |
| 面白さの中心 | 反射・上達 | **結果を人に言いたくなること** |
| ゲートで見るもの | 放置で死ぬ／上振れ／腕前 | **最後までたどり着ける／初見でも進める／画面が動く** |
| 「もう一回」の理由 | 記録更新 | **別の答えで別の結果を見る**・人にやらせる |

## state の形（進行の骨組み）

```ts
interface QuizState extends BaseState {
  /** いま何問目か（0始まり）。全問終わったら結果へ */
  q: number;
  /** 選んだ答え。結果はここから計算する */
  answers: number[];
  /** 'ask'（待っている）| 'reveal'（選んだ反応を見せている）| 'result' */
  phase: 'ask' | 'reveal' | 'result';
  /** reveal の残り時間。dt で減らす（setTimeout は使わない） */
  wait: number;
}
```

- **止まっていても `step` は毎フレーム呼ばれる**。`ask` の間は何もしないだけ
- 待ち時間は state のタイマーで（`n.wait -= dt`）。演出のために `setTimeout` を書かない（lint が止める）
- **`over` は結果画面を出したあと、タップで立てる**。結果画面はゲーム側で描く
  （共通シェルのリザルトは「点数と称号」なので、診断の結果画面は draw の中で描く必要がある）

## 選択肢の入力（1ボタンで選ぶ）

- 既定の `tap` で足りる: **選択肢に順番にカーソルが回る → タップで決定**（当時のケータイの十字なし操作）
- 2〜4択なら `aim`（画面のどこを押したか）でもよい。**その場合 `meta.control` を `aim` に**（記録の関所が見ている）
- 🔴 **`bot()` は「答えを持っている人」として書く**。ランダムに選ぶだけだと
  「最後までたどり着ける」は通っても「初見でも進める」の意味が消える。
  クイズなら正解を知っている bot、診断なら一貫した性格で答える bot

## 結果の設計（ここが本体）

**oneshot の面白さは、結果画面が「貼りたい・言いたい」かで9割決まる。**

- **二つ名を必ず出す**（数値やレーダーチャートではなく名前。era-2005 §診断の構造）
- **断言3行 ＋ 相性 or ラッキー1行**の型。留保をつけない（占いの重さ）
- **共有文は `meta.goals` を使う**: いまの共有機能は「称号になりました（N点）」を組み立てる。
  診断なら**結果タイプごとに固定の score を割り当て、`goals` にタイプ名を並べる**と、
  共有文が「即レス小悪魔になりました」の形でそのまま出る（`share.ts` を触らずに済む）。
  score が「点数」に見えないよう `unit` は空文字か「タイプ」にする
- 診断ロジックを AI に丸投げしたなら、**結果画面にその事実を1行**（「この診断はAIが勝手に考えました」）

## クイズの場合の追加

- **問題は AI に作らせる。正誤は人が検品**（[genre-crossover.md](./genre-crossover.md)）
- 出題順は `rng` でシャッフル。**同じ種なら同じ順**（おだいURLで「同じ問題で勝負」が成立する）
- 得点は「何問目まで／何問正解」。称号は正解数の段階で（`goals`）
- 1回20〜30問まで。100問は規模の憲法の外（[fun-doctrine §0](./fun-doctrine.md)）

## ゲートで見ているもの（と、見ていないもの）

oneshot で効く項目は **再現性・記録の一致・初見でも点が入る・腕前が効く・画面が動く・最後までたどり着ける**。

- 「初見でも点が入る」は**選ぶだけで1点入る**設計にする（進めたこと自体を加点）
- 「腕前が効く」はクイズなら正解率で自然に立つ。**診断は立たないことがある**
  （どう答えても結果は出る）→ その場合は `meta.funGate` で **理由をコメントに書いて** 外す
- **見ていないもの**: 結果が面白いか・共有したくなるか。**ここは playtest でしか分からない**。
  診断・クイズは playtest の6問に加えて自分に問う——**「結果を誰かに見せたくなったか」**

## 見せる（動画）側の注意

- 診断は「AIが考えた質問」と「出てきた結果」の**ギャップ**が見せ場。作っている途中の質問案を映す
- クイズは視聴者が一緒に答えられるよう、**問題を画面に大きく・答えを出す前に間**を置く
- 結果画面は決めの瞬間（punch）の置き場所

## 型の外に出るとき

- 2人交代（相性診断・家族クイズ）: **1台を回す**。state に `player: 0|1` を持つだけ。サーバーは持たない
- 画像が本体の題材（写真クイズ）: **いまの器では作れない**。言葉と図形で成立する形に畳む
- 「本当に1日従う」「実地検証」: 動画側の企画。ゲーム側は判定して終わりでよい
