# 収録レギュレーション


> **実際に撮るときの手順は [recording スキル](../../.claude/skills/recording/SKILL.md) にあります。**
> ここは番組としての決めごと（何を守るか）を書く場所で、あちらは段取り（どう動かすか）です。

## シリーズの考え方

**制約そのものが企画**。毎回同じ「30分開発」ではなく、制限のほうを変えて遊ぶ。

- コーヒー1杯を飲み終わるまで
- ポテトMを食べ終わるまで
- カップ麺ができる3分
- 新幹線が小田原から東京に着くまで
- 買い物から帰ってくるまで

**残り時間が画面に映るもの**ほど強い。ポテトは減っていくのが見えるので、それ自体がタイマーになる。

## 大前提：完成しなくても動画は成功

時間内に完成しないこと自体はオチになる。

- AIが意味不明な方向に行った
- 最後の30秒で壊れた
- 見た目だけ完成した
- 意外と普通にできてしまった

どれも成立する。**完成させることが目的ではなく、制約のなかで何が起きるかが中身**。

ただし、**リポジトリには未完成のまま残さない**。撮影後に仕上げてから公開し、
動画では「このあと直しました」と正直に言う。遊びに来た人が壊れたものを触るのが最悪。

## 作るものの規模（毎回同じ）

制作時間は毎回変わるが、**作るものの規模は変えない**。

- 1プレイ 30秒〜2分
- 一気に遊んで15〜30分でひととおりやりきれる
- 時間が余ったら、要素を増やさずに密度を上げる

詳細は [../design/fun-doctrine.md](../design/fun-doctrine.md) §0。
7日もらっても100ステージ作らない。**大きいものは、作りきれないし遊びきれない。**

## 既存作を下敷きにする回

「あの頃のあれを再現する」企画は、**撮影前に調査を済ませておく**。
撮影中に調べ始めると、企画の話で終わって作り込みまで届かない。

- 調査の進め方: [../../.claude/skills/research-classic/SKILL.md](../../.claude/skills/research-classic/SKILL.md)
- 元作品の名前・キャラ・見た目は持ち込まない（[../research/README.md](../research/README.md) §⑤）
- 動画では「参考にして自分たちで作った」と分かる形で話す

調査で分かった「なぜ流行ったのか」を撮影中に話すと、それ自体が中身になる。

## カンペを映す（dead air 対策）

開発中いちばん退屈なのは、AIが作業していて画面にコードが流れるだけの時間。
そこを埋めるために、**いま何をやっているかを出すカンペ**を用意してある。

収録用の起動コマンドを使うと、ログの初期化・チェックリスト表示・カンペの自動起動まで済む。

```bash
npm run dev:rec
```

手で操るときは次のとおり。

```bash
npm run live -- clear                     # 収録のはじめに1回
npm run live -- timer start 12 "ポテトM"  # 制限時間をスタート
npm run live -- phase きかく              # きかく → じっそう → けんてい → ためし
npm run say -- "ボットが全滅した"          # いまの一言（画面の主役）
```

カンペは開発サーバーの **http://localhost:3020/live**。別ウィンドウで開き、録画に映す。
面白さゲート（`npm run fun`）の結果は自動で流れるので、
**検定に落ちて直す過程がそのまま画になる**。

収録が終わったら、**エンディングカード**を開く。

**http://localhost:3020/live/result**

その日の開発が、ゲームのリザルト画面と同じ様式でまとまって出る
（かかった時間・ゲートが何回目で通ったか・書いた行数・いちばんの死因・できたもののURL）。
動画の締めにそのまま映せるし、スクリーンショットを撮ればXに貼れる。

そのあと台本を書き出す:

```bash
npm run live -- archive    # docs/worklog/ に台本として書き出す
```

`00:00 ポテトM スタート` のような**タイムスタンプ付きの台本**が出る。
テロップ原稿・チャプター・「何分で何が起きたか」がここから起こせる。

> 一言は**短く・声に出す内容と同じに**する。読ませる文章ではなく、視線を戻すための札。
> 迷ったら「いま何に困っているか」を書くと、視聴者がいちばん知りたい情報になる。

## 撮影中の注意

このリポジトリは **PUBLIC**。画面に映るものがそのまま公開される。

- ターミナルに他プロジェクトの情報を出さない（別ウィンドウで開く）
- `.env` やパスワードマネージャを開かない
- 他社・他案件のファイルが見えるエディタを映さない
- ブラウザのブックマークバー・タブを整理しておく

## 当日の段取り

### 前日まで
- [ ] 制約（何を食べ終わるまでか）を決めて、現物を用意する
- [ ] 既存作を下敷きにするなら調査を終えて `docs/research/` に置く
- [ ] `npm ci` が通る状態にしておく（撮影中にインストールで止まらない）
- [ ] 画面共有用のウィンドウ配置を決める

### 撮影直前
- [ ] `git pull` して最新にする
- [ ] 開発サーバーを一度起動して落としておく（初回コンパイルを済ませる）
- [ ] 通知を切る（Slack・メール・カレンダー）
- [ ] 録画の音声レベルを確認する

### 撮影中
- [ ] 最初に「何を作るか」を10秒で説明する（手描きでよい）
- [ ] 制約の現物を画面に置く
- [ ] AIへの指示は声に出して言う（何を頼んだかが視聴者に分かる）
- [ ] 途中で必ず一度遊ぶ（できたものを触る画がないと結果が伝わらない）

### 撮影後
- [ ] 未完成なら仕上げる
- [ ] `npm run fun -- <slug>` を全部緑にする
- [ ] 自分で3回遊ぶ
- [ ] `npm run check` を通す
- [ ] push して本番で開けることを確認する
- [ ] `meta.video` に動画URLを入れる（一覧からリンクされる）

## 公開後

- 概要欄にゲームのURLとGitHubのURLを載せる
- **自分が動画で遊んだのと同じ盤面**を配れる。リザルトの「おだいURL」を押すと
  `…#s=1234` 付きのURLがコピーされるので、それを概要欄に貼る
  →「動画と同じお題で勝負できます」が成立する（サーバーは要らない）
- 遊んだ人が記録を共有できる（リザルトの「記録を送る」がXの投稿画面を開く）
