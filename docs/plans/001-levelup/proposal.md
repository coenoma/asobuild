# 桁違いに伸ばすための強化案（優先度順）

> 2026-08-11 作成。**実装前の提案ドキュメント**。効果と工数を見比べて優先度をつけた。
> ここから着手するときは、1項目ずつ `docs/plans/` に設計を切って進める。

評価軸は4つ。各項目にどれへ効くかを付けている。

| 記号 | 意味 |
|---|---|
| 📺 | 動画が伸びる（画になる・フックになる・切り抜ける） |
| 🎮 | 遊びの質が上がる（もう一回が増える） |
| 🧱 | 安定する（収録中・公開後に壊れない） |
| ⏱ | 制作・編集が速くなる（1本あたりのコストが下がる） |

工数の目安: **S**=〜1時間 / **M**=半日 / **L**=1日〜（AI実装前提の体感値）

---

## 0. この提案の土台：いまの設計が持っている「構造的な配当」

基盤づくりの段階で入れた制約が、実はそのまま強化の原資になっている。
本提案の大半は、**すでに払ったコストの回収**であって、新しい借金ではない。

| すでにある制約 | それが可能にすること |
|---|---|
| `step` が純粋関数＋シード乱数（再現性） | **リプレイ・ゴースト・お題URL・死亡リプレイ**が入力記録だけで完全再生できる。ズルのできない公正なスコア比較も成立する |
| `bot()` 必須 | **アトラクトモード（デモプレイ）**・検証映像・「AIが1万回遊ぶ」演出に、そのまま転用できる |
| `Painter` が 2D コンテキストにしか依存しない | **node-canvas でサーバー側でも同じ絵が焼ける** → OGP画像・サムネ素材・Shorts動画を自動生成できる（この Mac で不安定な headless Chrome を使わずに済む） |
| 面白さゲートが純粋TS（Node依存なし） | **ブラウザ内でもゲートが走る** → 判定の様子そのものを画面で見せられる |

普通のゲーム開発ならどれも高くつく機能が、この設計だと安い。ここを取りに行く。

## Tier 1 — すぐやる（合計1日で全部入る。次の収録前に揃えたい）

### 1. 収録カンペ・ライブオーバーレイ `/live` 📺📺📺 ⏱⏱⏱（M）

**開発中に「今なにをやっているか」を、レトロ画面風のカンペとしてブラウザに常時表示する。**
録画はこのウィンドウごと映す。視聴者は AI の作業中も「いま何が起きているか」を読めるので、
dead air（無言でコードが流れるだけの時間）が消える。

表示するもの:

- 現在フェーズ（きかく → じっそう → けんてい → しゆう）
- いまの一言（大きな文字。「ボットが全滅した」「ゲート2回目、いく」）
- 制約タイマー（ポテト残量バー風。減っていくのが見える）
- 面白さゲートのチェックリスト（項目が緑に点灯していく）
- 直近の出来事ティッカー

仕組み（案）:

- `.live/status.jsonl` に1行JSONを追記する小さな CLI（`npm run say -- "文言"`）
- `fun-check` が判定結果を自動で追記
- Claude Code hooks（PostToolUse）でツール実行の要約を自動追記（うるさければ手動 say だけに落とす）
- dev 専用 API route がファイルを読み、`/live` がポーリング表示。**本番ビルドには含めない**

**副産物が本体級**: `status.jsonl` はタイムスタンプ付きの**編集台本**になる。
テロップ原稿・チャプター・「何分で何が起きたか」がそのまま残るので、編集時間が大きく減る。

リスク: hooks 自動要約は粒度が粗いと騒がしい。手動 `say` ＋ ゲート自動の2本から始めて様子を見る。

### 2. アトラクトモード 📺📺 🎮🎮🎮（S）

タイトル画面の背後で、**smart ボットが半透明でデモプレイし続ける**。
ゲームセンターの筐体と同じ「アトラクトモード」。

- ページを開いた瞬間に遊び方が見える（説明ゼロの理解がさらに速くなる）
- 「AI が自分の作ったゲームを自分で遊んでいる」という画そのものが番組的
- `bot()` 必須ルールの見返りが、視聴者に見える形になる

実装は GameShell の title フェーズで bot 入力の advance を回すだけ。数十行。

### 3. ガラケー和音ジングル 🎮🎮🎮 📺📺（S-M）

いまの単発ビープに加えて、**3和音着メロ風の短いジングル**（周波数＋長さの音列プレイヤー）を持つ。

- タイトルイン／スタート／自己ベスト更新／称号獲得／ゲームオーバー の5本、各1秒以内
- 音源ファイルは持たない方針のまま（WebAudio 合成）
- 「あの頃のケータイの音」は映像で流れた瞬間に効く。空気を作る費用対効果が最も高い部類

### 4. CI＋ゲート結果の記録・回帰検知 🧱🧱🧱（S-M）

いま `npm run check` はローカル頼み。これを仕組みにする。

- GitHub Actions: push/PR で `npm run check`（型・全ゲート・ビルド）
- **ゲート結果を JSON で記録**（`docs/records/gate/<slug>.json`）し、前回比で大きくドリフトしたら警告
  → 「ランタイムを触ったら既存ゲームの手触りが変わっていないか見る」ルールを機械が見張る
- 週次 cron でシードをずらした回を実行（固定シードへの過学習を検知）

### 5. レトロクラッシュ画面 🧱🧱 📺（S）

ErrorBoundary ＋「エラーが はっせい しました」のピコピコ画面＋もう一回ボタン。
公開後の保険であると同時に、収録中に出ても**それ自体がネタになる**安全網。

### 6. 収録モード `dev:rec` 📺📺 🧱（S）

収録用に整えた dev 起動コマンド。

- Next の開発インジケータ非表示（画面隅の「N」バッジは録画に映り込む・実測済み）
- ポート固定・`/live` を自動で開く・通知OFFのリマインド表示
- 収録レギュレーションの「撮影直前チェック」を1コマンドに畳む

## Tier 2 — 本命（各 半日〜1日。番組の「看板」を作る）

### 7. ゲート可視化ページ `/gate` 📺📺📺 🎮（M）

面白さゲートは純粋TSなので**ブラウザ（Web Worker）でそのまま走る**。それを見せ物にする。

- 数百〜1万回のプレイが走る様子をライブ描画（スコア分布のヒストグラムが積み上がる／ミニ画面で数プレイが実際に動く）
- 判定項目が1つずつ点灯していき、最後に「合格」がバーンと出る
- **「AI が1万回遊んで、面白さを数字で判定する」は番組の看板シーンになる**。サムネ・冒頭フックの定型にできる

必要な変更は runFunGate に進捗コールバックを足す程度。判定ロジック自体は共有のまま（二重実装しない）。

### 8. 開発リザルト画面（エンディングカード） 📺📺📺 ⏱⏱（M・#1に依存）

`/live` のログと git から自動集計して、**開発セッションそのものをレトロなリザルト画面にする**。

> きょうの開発
> 実装 12ふん ／ ゲート 3かいめで合格 ／ AIが書いた行数 214
> しぼう原因1位:「見のがし」 ／ 完成品: asobuild.coenoma.com/g/xxx

- 動画のエンディングカードがワンクリックで出る（毎回の編集で作らなくていい）
- そのまま X 投稿画像になる
- 「ゲームのリザルト画面の様式で、開発をリザルトする」という入れ子がシリーズの発明になる

### 9. リプレイ基盤 🎮🎮🎮 📺📺📺（M-L・段階導入可）

決定論の配当の本丸。**入力（1ビット/フレーム）＋シードを記録するだけで完全再生できる。**

段階的に:

1. **記録**（シェル側で入力リングバッファ。ゲーム側の変更ゼロ）
2. **死亡リプレイ**（直前3秒をもう一度見せる。「今の死に方」が動画の切り抜きになる）
3. **ゴースト**（自己ベストの残像と一緒に走る。「惜しさ」の可視化として最強）
4. **お題URL** `/g/hanko#s=1234`（同じ出現順で勝負。決定論なのでスコア比較が公正）
   → 動画概要欄に「ぼくと同じ盤面はこちら」を貼れる。**サーバーなしで成立する対戦要素**
5. ボット vs 自分（AI の最善プレイと並走）

リスク: `aim` 系は px/py も記録が要る（データ量は数KB、base64 で URL に載る範囲）。

### 10. 難易度オートチューナ `npm run tune` ⏱⏱⏱ 🎮🎮 📺（M）

ゲームが調整用定数を `TUNABLES` として公開する規約を足し、
`npm run tune -- <slug> --param SPAWN --target smartSec=45` が**二分探索でゲート目標に合う値を提案**する。

- 収録中の「数字をいじる→ゲート→また いじる」往復が1コマンドになる（制限時間内の最大の時間食いを潰す）
- 「AI が自動で難易度調整しています」はそれ自体が画になる
- リスク: 多変数同時は発散する。**1変数ずつ**に限定する

### 11. 画像の自動生成（OGP・リザルトカード） 📺📺 🎮（M）

Painter が 2D コンテキスト汎用なので、**node-canvas でビルド時に同じ絵をサーバー側で焼ける**。

- ゲームごとの OGP（実プレイの1フレーム＋タイトル＋ケータイ枠、1200×630）を自動生成
  → X でリンクが貼られた瞬間の見た目が別物になる
- 共有時に**リザルトカードPNG**（スコア・称号入りのレトロカード）を生成して Web Share API で画像ごと共有
  → テキストだけの共有より流入が伸びる

依存: node-canvas（ネイティブ依存。devDependencies に閉じる）。

### 12. コレクション要素＋動画導線 🎮🎮 📺（S-M）

- トップに横断メタ称号:「全◯ゲーム中、称号コンプ◯個」（localStorage 集計。サーバー不要）
  → ゲームが増えるほど「全部埋めたい」が働く。**量産が正義になる設計**
- ゲームページに YouTube 埋め込み（`meta.video` は既にある）
  → サイト⇄動画の相互送客。「作っているところを見る」が1クリック

### 13. ボツ供養 📺📺 🎮（S）

ゲートに落ちた・お蔵入りになった作品を消さず、**「ボツ」ラベル＋落選理由つき**で別枠に陳列し、遊べるようにする。

- 「失敗が面白い」（broadcast-design）のサイト側実装
- 動画で「ボツでした」と言ったものが実際に触れる → 誠実さと笑いの両取り
- 実装は `meta` に status を1つ足して一覧を分けるだけ

## Tier 3 — 大玉（1日〜。量産ラインとプラットフォーム磨き）

### 14. Shorts 自動生成 📺📺📺（L・#9 #11 に依存）

リプレイ（決定論再生）＋ node-canvas ＋ ffmpeg で、
**ベストプレイ／死亡集を 1080×1920 の縦動画に自動で書き出す**。

- 毎ゲームに Shorts が1本「ついてくる」量産ライン。本編→Shorts→サイトの三角導線
- この Mac の headless Chrome は不安定（実測）なので、**Chrome 非依存の経路（node-canvas 直描画）で組む**のが勘所
- HUD はショート用に大きく焼き直す（240×320 をそのまま拡大しない）

### 15. 実機診断ページ＋モバイル磨き 🎮🎮 🧱🧱（M）

- `/diag`: fps・入力遅延（タップ→反映フレーム）・音・振動の動作確認ページ（実機検証を定型化）
- `navigator.vibrate` でヒット時に短く振動（スマホの手応えが一段上がる）
- PWA 化（ホーム画面追加でフルスクリーン起動＝「ケータイにゲームが入ってる」感）
- iOS Safari の注意点（音声解禁・100dvh・スクロール干渉）をチェックリスト化

### 16. アナリティクス ⏱（S）

Vercel Web Analytics で「どのゲームが遊ばれているか」だけ取る。
次にどの型・題材を作るかの判断材料。外部スクリプトが1本増えるトレードオフは明記の上で導入判断。

## やらないこと（引き続き明記）

| やらない | 理由と代替 |
|---|---|
| サーバーランキング・アカウント | no-server 原則。**代替＝お題URL（#9）**。決定論なので同一盤面の公正比較がサーバーなしで成立する |
| リアルタイム対戦 | 同上。ゴースト（#9）が非同期対戦の役を果たす |
| 広告・課金・ガチャ | 番組の趣旨と合わない |
| 汎用ゲームエンジン化・外部ライブラリ導入 | 依存を増やさない原則。唯一の例外は画像生成の node-canvas（devDeps に閉じる） |

## コード外で効くこと（運用）

1. **初回収録前に research-classic を2本回す**（チャリ走系1・糸通し系1）。
   feel-catalog に数値が貯まり、#3（ジングル）#10（チューナ目標値）の根拠になる。調査自体も動画の題材になる
2. **公開チェックリストをエピソード単位に**（収録レギュレーションへ追記）:
   ゲート緑 → 3回遊ぶ → 権利チェック → OGP確認 → 概要欄にゲームURL＋お題URL → X投稿
3. **「1万回検証」を番組の定型フックに**（#7 の演出をサムネ・冒頭に使い回す）
