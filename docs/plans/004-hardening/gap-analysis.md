# いまの穴と、埋め方

> 2026-08-11。基盤・強化・実作3本・別セッションでの制作を経て分かったことの棚卸し。

## 1. 機械にできること／人にしかできないこと

ここを取り違えたまま「完成」と言うのが、いちばん危ない。

### 機械が担保できる（自動で落とせる）

| 対象 | 手段 |
|---|---|
| 型・ビルドの正しさ | `npm run typecheck` / `build` |
| 面白くなりようがない状態 | 面白さゲート12項目 |
| 手触りが勝手に変わっていないか | ゲート記録との比較（±25%） |
| 今の種でたまたま通っていないか | 週次CIで種をずらして実行 |
| 難度の当たり | `npm run tune`（二分探索） |
| プレイの再現性 | 種＋入力列で完全再生（実測済み） |
| 遊んだ記録があるか | `npm run ship` |

### 人にしかできない（機械は「無いこと」しか分からない）

| 対象 | なぜ機械にできないか |
|---|---|
| **面白いか** | ゲートは「面白くなりようがない」を弾くだけ |
| **何をすればいいか伝わるか** | 画面から意味が読み取れるかは、数字に出ない |
| **見た目の質** | 自作の絵に「完成」と言えるのは人だけ |
| **権利の最終判断** | 「誤認するか」は人の感覚 |

### AI（このセッション）にできないこと ★ここが盲点だった

| 対象 | 理由 |
|---|---|
| **実際に遊ぶ** | ブラウザ自動化では、タブが裏に回ると `requestAnimationFrame` が止まる。動きのあるものを触れない |
| **見た目の良し悪しを決める** | 静止画は撮れるが、それは機能確認であって品質判断ではない |
| **playtest の記録をつける** | 遊んでいないので答える資格がない |

**この3つは、AIが「やった」と言ってはいけない。** 人に渡す。

## 2. 実際に起きた失敗と、その一般化

| 起きたこと | 一般化すると | 埋めた／埋める手 |
|---|---|---|
| ゲート緑のまま面白くないものを公開した | **緑＝完成、と誤解する** | `playtest` + `ship`（実装済み） |
| 1プレイ158秒が素通りした | **ドキュメントの目安とゲートの基準が食い違う** | § 3-A |
| でたらめボットが構造的に成功できなかった | **ボットの都合が、ゲームの評価にすり替わる** | 押す長さを散らす形に修正（実装済み） |
| 試行80回で「56分」と誤判定した | **サンプル不足のまま断定する** | 到達5回未満は判定保留（実装済み） |
| 未コミットの成果物が放置された | **作業の完了状態が誰にも見えない** | § 3-B |
| カンペがほぼ使われなかった | **作った機能が使われたか分からない** | § 3-B（状態表示に含める） |
| 同じツリーを複数セッションが触った | **競合の作法が決まっていない** | § 3-C |

## 3. これから埋める穴

### A. ドキュメントとゲートの食い違いを検出する

`fun-doctrine.md` の「数字の目安」と、ゲートの実際のしきい値が、別々に書かれていて同期していない。
実際に「1プレイ40〜90秒」と書きながら上限240秒で運用していた。

→ **`npm run status` で両方を並べて出す。** 人が見て気づける状態にする。
（数値を1か所に寄せる案もあるが、ドキュメントは人が読むためのもので、
文脈つきで書かれている価値がある。機械が照合して見せるほうが実態に合う）

### B. リポジトリの「健康状態」を1コマンドで出す

いま何が終わっていて何が終わっていないかが、複数の場所に散っている
（git の状態・ゲート記録・playtest記録・OGP・公開状態・カンペのログ）。

→ **`npm run status`** で一望する。特に見るのは、

- 公開されているのに**遊んで確かめていない**ゲーム
- 実装を直したのに**記録が古い**ゲーム
- **未コミット**の成果物
- 使われていない仕組み（カンペなど）

### C. 複数セッションで同じツリーを触るときの作法

別セッションが `GameShell` を触っている最中に、こちらもコミットしかけた。
向こうは気づいて「コミットしていません」と申告してくれたが、**運任せ**だった。

→ ルールを明文化する（作業前に `git status`／コミットは自分の担当分だけ／
`cmux send` で他セッションに命令を送らない）。

### D. 「AIができないこと」を規範に書く

上の 1-③ が、どこにも書かれていなかった。
「実機で確認しました」と言えないことを、はっきり書いておく。
