## 機械で確かめたこと

- 既存4本のゲート数値は一連の変更を通して**不動**（記録比較・警告なし）
- 仮想の arcade レース（steer）と flash タイピング（type+novice）でゲート全項目が意味を持って回る
- 記録から steer / typed / px を落とすと**リプレイ関所がちゃんと落ちる**（歯の確認）
- これらは selftest として恒久化した（一時スクリプトで確認→削除、をやめた）

## 📌 残っている観点（今回の振り返りで棚卸し。上ほど先に効く）

1. **playtest 指紋はランタイムを含まない**（設計上の割り切り）。ゲートの数字が動かない
   手触りの変化（入力・シェル）は機械では捕まらない → 運用ルールとして arcade.md に明文化済み。
   これで足りるかは、実際にランタイム起因の手触り事故が起きたときに見直す
2. **文書のリンク切れ検査が無い。** 地図系文書（platforms / genre-map / はじめかた / AGENTS）に
   相対リンクを大量に足したが、機械で見ていない。md の相対リンク存在チェックは30行で書ける。
   次に文書を大きく動かすときに関所化を検討
3. **OGP・スクショの横長対応は仮の縮小式のみ。** 最初の flash / arcade 企画で絵として作り直す
   （ショート＝縦動画と横長画面の相性もそのとき決める）
4. **main 直 push ＝即本番。** 今回のようなランタイム広域変更は、ブランチ＋PR プレビューで
   人が見てから main に入れる運用も選べる（判断はオーナー）
5. **整備セッションのゲート実行が `.live`（収録カンペのログ）へ混ざる。** 収録は開始時刻で
   切り出すので実害は小さいが、気になったら「収録モード中だけ記録」へ寄せる手はある
6. **型×機種×操作の組み合わせ禁則が表になっていない**（例: type×keitai は禁止ではないが無意味）。
   迷う人が出たら platforms.md に表を足す
