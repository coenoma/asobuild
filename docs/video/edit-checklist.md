# 編集の関所 ── 出す前に通す

**ゲームに面白さゲートがあるのと同じで、動画にも関所を置く。**
ここに並んでいるのは、001回で**実際に人が見て指摘された**ことを一般化したもの。
原則ではなく、**起きた事故のリスト**なので、毎回そのまま通す。

映り込み・権利は [safety-checklist.md](./safety-checklist.md)（別の関所）。ここは**編集の質**の話。

```bash
cd video
node scripts/sync-check.mjs edl/<slug>.json   # 言っていることと映っているもののズレ
node scripts/voice.mjs edl/<slug>.json --synth # 声の長さと食い込み
```

---

## 1. タイミング ── ここが気持ちよさに直結する

> 001での指摘: 「7分半考えてる のテロップ・声のときに、画面がすでに補足を投入している画面になっちゃってて違和感」
> 「『あ、なんかできてる』が0.5秒とか、びみょうーに早くて違和感」

**細かいタイミングのズレは、内容の間違いより強く違和感になる。** 1つずつ慎重に。

| 決まり | なぜ |
|---|---|
| **反応の行は、出来事の 0.3〜1.2秒あと**に置く | 人は見てから声が出る。同時・先回りは「予知」に見える |
| **まだ起きていないことを、先に言わない** | 「一覧に出てる！」の直後に出てくると、嘘に見える |
| **その時刻の画面に、まだ起きていないはずのものが映っていないか** | 全体を映すと未来が映り込む。**寄って隠す**（下記2）|

原稿の行に `after` を書くと機械が見張る。

```json
{ "at": 5.2, "t": "あ、なんかできてる！", "after": { "clip": "sca-list", "at": 4.5 } }
```

→ `sca-list` の4.5秒地点が出来事。5.2は0.7秒あとなので通る。4.0なら**落ちる**。

## 1.5 時計を1本にする（いちばん事故る）

> 001での指摘:「7分半と言っているのに、右上の経過時間が5:45でつじつまが合ってない」
> 「11m3sなのに右上は12:52。全体的にこういったシーンでは確実に同期をとって」

**画面には時計が2つある。** AIの「◯m◯s thinking」と、こちらが出す経過時間の帯。
食い違うと、見ている人は「どっちが本当？」で止まる。

1. **実測で対応をとる。** 001では「開発の時計 ＝ 画面収録の時刻 ＋ 48秒」が一致した
   （依頼を投げたのは収録開始の48秒前だった）。EDL の `meta.devOffset` に書く
2. **帯の時刻は映像から引く。** 章の頭と尻を線で結ぶと、章のなかで素材が飛んだときにズレる。
   `ProgramBar` は**いま映っている素材の時刻**をそのまま出す（`marks`）
3. **素材は時系列に並べる。** 「まだ考えてる」の数字が前後すると、順番が壊れて見える
4. 台詞で言う分数は、**その画面に映っている数字と合わせる**
5. **時計は戻さない。止めもしない。**
   時計が戻るのは「素材を時系列でなく話の都合で並べた」サイン。**並びのほうを直す**のが本筋。
   数秒のズレなら、素材の頭を数秒うしろへずらすだけで消える（中身は同じ）。
   どうしても前の画をもう一度見せたいときは `recap: true` を書く。
   帯は時刻のかわりに**「ふりかえり」**と出すので、戻っても止まっても見えない
6. **時計を出さない章があってよい。** つかみ（`hook`）と、思い出す・図解だけの章（`recall`）は `noBar`

**`sync-check.mjs` が見張る。** 時計が戻る並びは ✗ で落ちる:

```
✗ 3:44.6 best/ugly-play で時計が戻る（16:46 ← 28:38）。素材の順を直すか、recap:true を書く
```

## 2. 画面の文字を読ませる ── 一例には触れる

> 001での指摘: 「チャット欄を全部読み上げる必要はないですが、ポイントだったり一例は触れるようにしましょうか。
> 気になる方は止めて読んでね、みたいな。なので、読めるようにもしないとだ
> （なんかずーっとにょいーんて動いてるけど、意味あるのか？）」

この番組の中身は**AIとのやりとりそのもの**。読めない画で流すと、いちばん濃いところが消える。

- **本文は寄りのcropを作って出す**（ターミナル全体を縮小して出さない）。
  001では `termAdd` `termReq` `termFb` を作った。**止めて読める大きさ**が基準。
  位置は勘で決めず、方眼を見て取る:

  ```bash
  node scripts/find-crop.mjs screen 466             # 方眼つきの1枚を出す
  node scripts/find-crop.mjs screen 466 0,780,960,440   # 切り出しを確認してから EDL へ
  ```
- **読ませるショットは動かさない**（`zoom` を付けない）。原稿の行に `"reads": true` を書くと機械が見張る
- **全部は読み上げない。1つだけ具体を言う**（「『失敗したときも、シュールに静かに終わる』とか」）
- **「気になる方は、止めて読んでみてください」を1回だけ言う**。毎回言うとくどい

## 3. 台本は「ぼくが実際に言いそうな日本語」か

> 001での指摘: 「操作、わかる！ も口語としては変だよね」
> 「はじめてのおわり ってなんだ？？？ 受け入れすぎ。これ、変だから、日本語として。つっこもうか」

書き方の本体は [voice-and-script.md](./voice-and-script.md)。関所としては次を見る。

- [ ] 声に出して読んで、**言いそうにない言い回しが無いか**（「操作、わかる！」→「あ、操作はわかりますね」）
- [ ] **画面の変な日本語を、そのまま受け入れていないか**。変なものには**ツッコむ**
      （ゲームの表示が「はじめてのおわり」なら、「日本語、ちょっと変じゃないですか？」まで言う）
- [ ] 感想の置き場所が合っているか（「それっぽい！」は**初めて見た瞬間**であって、あとから言うものではない）
- [ ] **視聴者に関係のない数字を言っていないか**（「1本、ふえました」＝リポジトリの本数。視聴者には無関係）
- [ ] **説明していないことを、分かっている前提で言っていないか**（「1本ももちません」＝何の1本か伝わらない）
- [ ] **AIが実際にやったことと、言っていることが合っているか**
      （「判定を甘くしてくれました」ではなく「針の穴を広げて、だんだん速くなるのと穴が小さくなるのを、なだらかに」）
- [ ] 遊べる場所の言い方が具体か（「いま、誰でも遊べます」→「概要欄のURLから、だれでも遊べます」）

## 3.5 メリハリ ── のっぺりさせない

> 001での指摘: 「もっとシーンの切り替わりとかを大々的にやったり、ゲーム画面との違いをメリハリ出したりしないと、
> 全体てきにのっぺりした印象の動画になるね」

**同じ調子で流れ続けると、内容が良くても「のっぺり」になる。** 節目で画を止めて、はっきり切る。

### 経過時間の判子（`timeStamp`）を節目ごとに打つ

制限時間そのものが企画なので、**時間は飾りではなく本体**。上端の帯は流し見だと目に入らない。

```json
{ "type": "timeStamp", "at": 0, "dur": 2.0, "value": "14分", "note": "経過", "sub": "なんか、できてる？" }
```

- 打つ場所: **できた／時間切れ／作り直し開始／まだ遊んでる／ぜんぶ終わった**
- 1本で4〜6回。多すぎると効かない
- 色を使い分ける（`accent`＝進んだ / `bad`＝まずい / `cool`＝仕切り直し）

### 待たせている時間も、画で見せる

「◯分考えている」は、**ターミナル全体ではなく、その行だけを大きく**出す
（`termThink` のような寄りcrop）。数字が刻んでいるのが見えると、待っていることが伝わる。

### 自撮りの色は、撮ったままで出さない

素人の自撮りに見える原因はだいたい「白飛び」「色かぶり」「眠さ」。
`extract.mjs` の `self` フィルタで、黒を少し浮かせ、白飛びを止め、肌を少し暖色へ、軽くシャープ。
**ビネットは入れない**（寄りの画では四隅の暗さが作り物っぽく見えた）。

ワイプは**角丸＋白い縁＋影**にして「番組側の窓」に見せる（`wipe: true`）。

### 変化は「指す」。映っているだけでは気づかれない

一覧に1本増えた、みたいな**小さな変化ほど見落とされる**。`spot` で囲って矢印を出す。

```json
{ "type": "spot", "at": 6.6, "dur": 4.0, "box": { "x": 3, "y": 61, "w": 30, "h": 29 }, "from": "right" }
```

位置は書き出した1枚を見て測る（`npx remotion still src/index.ts Episode /tmp/x.png --frame=<n>` →
`ffmpeg -i /tmp/x.png -vf drawgrid=w=96:h=54:t=1:c=red@0.6 ...` で方眼を重ねる）。
**素材が違えば位置も違う。** 同じ寄りでも行の位置がずれるので、1つずつ測る。
**囲った場所を、テロップで隠さない**（囲うなら文字は反対側へ）。

### 真っ黒の上で喋らせない

文字だけを見せたいときも、**黒地に字幕**では画が死ぬ。
言っている内容の映像を暗く敷いて（`scrim`）、文字を**真ん中に大きく**出す。

### 時刻の小さい表示は、その場しのぎで作らない

「◯分」を画面の隅に添えたいときは `timeStamp` の `variant: "chip"` を使う。
`note` テロップで似たものを都度作ると、**位置も見た目もバラバラの札**が残る（001のFB）。

### 締めの前に、区切りを1枚入れる

結論に入る前に「おつかれさまでした」の判子を置く。
**切り替わることを予告してから結論を言う**と、最後まで見てもらえる。

## 4. テロップは、ゲームに馴染ませない

> 001での指摘: 「テロップ・字幕、全体的にゲームの雰囲気に馴染みすぎて、逆に全然読みにくい」
> 「ゲーム画面に『似た雰囲気』でテロップ的なものを重ねるとゲームなのかなんなのか紛らわしい」

**盤面と同じ色・同じ大きさの札を重ねると、「ゲームのUI」に見えて文字として読まれない。**

- **明暗を逆にする。** 盤面が「暗い地に薄い文字」なので、番組の文字は**明るい地に黒い文字**。
  黒い帯にして大きくするだけでは直らなかった（同じ指摘を3回もらっている）
- 色は**枠**にだけ使う。地と文字は明るい地／黒で固定
- 盤面の色（`bg` `bg2` `line` `ink`）を、テロップの地にも文字色にも使わない
- **点数の判子も同じ明るい札にする**（暗い札に色の数字だと、盤面の点数表示とそっくりになる）
- **点数を盤面の真ん中に重ねない**（`BigNumber` は `place: 'right'`）。
  ゲーム自身が点数を出しているので、同じ位置に同じ数字を出すと
  「動画が点数を足している」ように見える（001のFB）
- **読ませる画は、字幕の帯にかからない箱に収める**（`{x:4, y:11, w:92, h:62}`）。
  全画面に伸ばすと、下の数行が帯で隠れて**止めても読めない**
- 詳細と実装: [telop-rules.md](./telop-rules.md)

## 5. 盤面は全体を見せる。プレイ中は顔を出す

> 001での指摘: 「プレイ動画のところは、同期がとれてる自撮り動画を左下だか的説なところに窓？ワイプ？みたいな感じで入れておこうか（全体的に）」

- **ゲームは枠に収める**（`fit: contain` ＋ `box`）。全画面に伸ばすと点数・死因が枠外に出る
- **プレイ中は自撮りをワイプで入れる**。ゲーム中は無表情で真剣、失敗した瞬間に顔が動く。
  そこが見どころになる（[footage-notes/](./footage-notes/) の反応表）
- ワイプの定位置は**右下**（`{x:81, y:50, w:16, h:29}`）。字幕の帯にかからない高さ。
  **顔の向きに合わせる**（001の自撮りは右向きの画角なので、左に置くと外を向いてしまう）
- ワイプの層には `"wipe": true` を書く（主役のショットではない、という印。機械がこれで見分ける）
- 自撮りの尺は画面収録より**短いことがある**。無い区間はワイプ無しでよい（無理に伸ばさない）

## 6. 締めは動かす

> 001での指摘: 「しめの画面・ナレーションも、固定表示すぎるから、順番にだすなり、もっとみやすくするなり」

**いちばん離脱してほしくないところで、17秒間まったく動かない画にしない。**

## 6.5 音

**同じ出来事にはいつも同じ音**を当てる（[sound-design.md](./sound-design.md)）。

- [ ] タイトルカードに**タイトルコール**が鳴っている（毎回同じもの）
- [ ] 場面の判子に**風切り＋一撃**が付いている
- [ ] `sting`（結論の一撃）を**1本で1回しか使っていない**
- [ ] **同時に3音より多く鳴っていない**（ジングルの中の和音も数える）
- [ ] **判子に別の音を重ねていない**（風切り→一撃の2つだけ）
- [ ] 同じ音を連打していない
- [ ] 効果音を外から持ち込んでいない（PUBLIC なので再配布になる）
- [ ] BGM は `video/bgm/`（gitignore）に置いてあり、**コミットされていない**
- [ ] BGM が喋りを邪魔していない（下に敷く曲は頂点 -32dB が目安）
- [ ] **概要欄に曲のクレジットを書いた**

## 6.8 書き出す前に、ディスクの空きを見る

**11分の描画は、Chromeの作業領域と一時ファイルで数GB使う。**
空きが足りないと、**出力もログも残さずに強制終了される**（001で2回起きた。原因が分かるまで時間を溶かした）。

```bash
df -h /System/Volumes/Data | tail -1    # 空きが 15GB を切っていたら片付けてから
du -sh ~/Library/Caches/* | sort -rh | head   # だいたいここが太っている
```

- 目安は**空き15GB以上**。10分を超える動画ならもっと
- ブラウザのキャッシュは消しても作り直される（ログイン状態は消えない）
- 描画が「何も言わずに落ちた」ときは、まずここを疑う

### 確認は書き出しを待たない

**`npm run studio --prefix video` がいちばん速い。** ブラウザで再生位置を掴んで動かせ、
EDL を直すとその場で反映される。**声・BGM・効果音まで鳴る**（合成に入れてある）。

| やりたいこと | コマンド | かかる時間 |
|---|---|---|
| 1か所だけ確かめる | `npm run studio --prefix video` | 数秒 |
| 全体の流れを見る | `npm run draft --prefix video` | 数分（半分の解像度） |
| 人に見せる・出す | `npm run build --prefix video` | 30分前後 |

30分待ってから直しどころに気づく、をやめる。**直す→studioで見る→また直す**を回してから、
最後に1回だけ本番画質で書き出す。

リポジトリ直下から `npx remotion` を手で叩かない。①実行ファイルが見つからない
②`video/public/` を見に行かず**書体が無いと言って落ちる**、が続けて起きる（001で2回やった）。
**コマンドは package.json に固めてある。**

## 7. 全部を通して見る

- [ ] **結果画面が一瞬で切れていないか**（点数が出たあとを2秒以上見せる）
- [ ] **画面に出ている時刻と、言っている時刻が合っているか**（上端の帯と台詞）
- [ ] **意味のない画が挟まっていないか**（説明していない結果画面など）
- [ ] **字幕が点滅していないか**（隣り合う字幕を一瞬だけ消すと、読めない札が出たように見える。
      すきまは詰めるか 0.6秒以上あける。`sync-check` が落とす）
- [ ] **無音が3.5秒を超えていないか**（`sync-check` が見る。判子とタイトルは除外される）
- [ ] **声どうしが重なっていないか**（`--synth` の食い込みが0）
- [ ] **場面の頭に、前の場面の残りが映っていないか**（切り替わりきってから使う）
- [ ] **画面に映っている数字と、喋っている数字が一致しているか**
      （素材の切り方を変えたら `extract.mjs` が自動で切り直す。手で消す必要はない）
- [ ] **上端の帯の時刻と、画面のAIの経過表示が合っているか**
- [ ] **AIが考えたことを、自分が考えたように言っていないか**（提案はAI発だと分かる構成に）
- [ ] `node scripts/sync-check.mjs` が緑
- [ ] `node scripts/voice.mjs --synth` の食い込みが0
- [ ] **喋りっぱなしになっていないか**（効果音だけ・映像だけの間が数か所あるか）
- [ ] 章の切れ目で息が継げるか
- [ ] スマホの大きさで字幕が読めるか
- [ ] **人が最後まで通しで見た**（AIはこれを「やった」と言ってはいけない）
- [ ] **仕上げの音量が -14 LUFS になっている**（build の最後に master.mjs が数字を出す。
      公開に使うのは `out/<slug>-master.mp4`）
- [ ] **人が音を聴いた**（AIは音の良し悪しを判断できない）
- [ ] 本番画質で書き出す前に、**studio か draft で一度は通して見た**
