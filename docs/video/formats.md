# 番組の企画フォーマット ── アソビルドは「これ、AIと作ったらどうなる？」

[video-doctrine §0](./video-doctrine.md) の「これは実験の記録」を、**企画の型**まで落としたもの。
題材探しはここと、大衆需要側の [genre-crossover.md](../design/genre-crossover.md) を両輪で使う。

---

## ポジション（他チャンネルとの違い）

IT実験系の王道は、どれも「対象 × ひとつの動詞」でできている。

| チャンネル型 | 一言 |
|---|---|
| 生き物実験系 | 「これ、捕まえたらどうなる？」 |
| セキュリティ系 | 「これ、ハックしたらどうなる？」 |
| 変なコンピューティング系 | 「Excelでこれ作ったらどうなる？」 |
| 全自動化系 | 「全部自動にしたらどうなる？」 |
| **アソビルド** | **「これ、AIと作ったらどうなる？」** |

だから題材はゲームに限らない。**AIと、遊ぶようにつくる**に収まるものは全部候補。
ただし「AI開発チャンネル」にはしない——**IT好きじゃない人がクリックする一般性**を毎回通す
（物差しは genre-crossover の5つ）。

## 🔴 番組の芯 と asobuild リポジトリは別物

ここが混乱の元なので最初に固定する。

- **番組（YouTube）**＝「AIと作ってみた」の記録。題材は無限
- **asobuild リポジトリ**＝**サーバーなし・ログインなしで、その場で遊べるミニゲームの置き場**
  （[README](../../README.md)・[fun-doctrine やらないこと](../design/fun-doctrine.md)）

IT実験側の企画は、**遊べる成果物がリポジトリに載らないものが多い**（サーバーが要る・
その場の環境でしか動かない）。それは失敗ではなく、**そもそも別物**。各企画で必ず分けて書く:

> **この回、asobuild に「遊べる形」で残るのは何か？**（無いなら「動画のみ」と明記する）

載らない回でも、**その過程で生まれた小さなゲームは asobuild に載せられる**
（例: 自動化の実験中に AI が作ったミニゲーム）。そこが番組とリポジトリの結び目。

## IT実験側の型（5つ）

### ① 再発明 ──「AIだけで◯◯をゼロから作れる？」

誰でも知っている対象を、AIと作る。**ガラケーゲーム再現とまったく同じ構造**（看板の兄弟）。

- 例: 昔のmixiを2026年に蘇らせる／Windowsっぽい画面／検索エンジンっぽいもの
- **asobuild 適性: ◎**（Web の見た目なら静的サイトで作れることが多い）
- 権利: 実在サービスの名前・ロゴ・トレードドレスを出さない。「◯◯**みたいな**」で言及に留める
  （[rights-and-originality.md](../design/rights-and-originality.md)）。再現度が上がるほど誤認テストを厳しく
- 「AIでアプリ作ってみた」単体は弱ってきている。**対象の知名度**で引く（題材変数は看板と同じ）

### ② 変な場所で作る ──「◯◯だけで△△作れる？」

面白いのは成果物ではなく **「なんでそこで作ったの？」**。制約が企画そのもの（看板の制約企画の親戚）。

- 例: スプレッドシートだけで／音声入力だけで／会話だけで／スマホだけで
- **asobuild 適性: △〜◎**（成果物が Web ゲームなら載る。ツール内で完結すると動画のみ）
- 実在事例: Excel の中に16bit CPU を作った動画が広く拡散し、大手技術メディアが軒並み報道した
  （個別再生数は伝聞。**外れ値を一般化しない** ── [research-notes](./research-notes/) の物差し）

### ③ 全部自動化 ──「ぼくの△△を全部AIに任せたら？」

Vlog 的な面白さが出る。「ツール紹介」ではなく **実際に一日その通り生活する** まで行く。

- 例: 1日の判断を全部AIに任せる／仕事を任せて何時間ヒマになるか
- **asobuild 適性: ✗（動画のみ）**。ただし過程で AI が作ったものは載せられる
- 🔴 ここは**サーバー・実生活・実データ**が絡む。asobuild の中では作らない。**別の作業場**でやり、
  リポジトリには「その回で生まれた遊べるもの」だけを持ち込む

### ④ 放置・検証 ──「人間が触らず、AIだけで◯時間やらせたら？」

見どころは「人間がいなくなったら、AIはどこまでやれる？」。一般人にも意味が分かる。

- 例: 24時間、無人でAIに開発させ続けたら／何も指示せず任せたら何を勝手に改善する？
- **asobuild 適性: 場合による**。成果物が遊べる Web ゲームなら載る。環境依存なら動画のみ
- 素材の作り方は動画側の工夫（タイムラプス・区切りの判子）。**放置中の無風をどう見せるかが勝負**

### ⑤ 無茶な物量 ──「1日でミニゲーム◯本作れる？」

**規模の憲法（§0）と衝突しない**——1本1本は15〜30分で遊びきる規模のまま、**本数**を増やす。
AI だからこそ物量が現実になる。**看板ジャンル・視聴者リクエストとの相性が抜群**。

- 例: 1日で10本／マックにいる1時間で何本／リクエスト10個ぜんぶ作る
- **asobuild 適性: ◎**（作ったゲームがそのまま並ぶ。一覧が育つ）
- 🔴 **数を言い訳に品質を落とさない**。10本でも1本ずつ `npm run fun` と playtest を通す
  （通らなかったものはボツ棚へ理由つきで。それも番組の中身）。**「10本できた（中身は空）」が最悪**

## やらないこと

- 🔴 **セキュリティ・ハッキング回はやらない**（2026-08-18 オーナー判断）。
  再生実績は大きいが、番組のトーンと合わず、PUBLIC リポジトリ・悪用リスク・
  サムネの印象いずれも噛み合わない。自分の所有環境限定でも、初期は避ける。
  「守り・直す」側の話をどうしてもやるなら、**別チャンネル・別企画**として切り出す（混ぜない）
- 実在サービスの再現で、名前・ロゴ・公式アセットを持ち込む（②再発明の権利と同じ）
- 「AIがこう言った」を、人が確かめずに事実として出す（[CLAUDE.md §AIには確かめられないこと](../../CLAUDE.md)）

## 企画の在庫（IT実験側。外部提案をふるったもの）

**在庫であって決定ではない**。着手前に「asobuild に載るのは何か」と genre-crossover の5物差しで再評価。

| 型 | 企画 | asobuild に載る？ | 注意 |
|---|---|---|---|
| 再発明 | AIだけで昔のmixiを2026年に蘇らせる | ◎ 静的サイトで | 名前・ロゴ出さない。「◯◯みたいな」 |
| 再発明 | AIだけでWindowsっぽい画面／検索っぽいもの | ◎〜○ | トレードドレスに寄せすぎない |
| 変な場所 | スプレッドシートだけでゲーム作れる？ | △ 成果がWebゲームなら | 面白いのは「なんでそこで」 |
| 変な場所 | 音声入力だけでWebサービス作れる？ | △ | 過程が主役。動画のみになりがち |
| 全自動化 | ぼくの仕事を1日ぜんぶAIに任せる | ✗ 動画のみ | 過程で生まれたものだけ持ち込む |
| 放置検証 | 人間が触らず、AIだけで24時間開発 | 場合による | 遊べる成果なら載せる |
| 無茶な物量 | AIと1日でミニゲーム10本 | ◎ 一覧が育つ | 数を言い訳に品質を落とさない |
| 無茶な物量 | 視聴者リクエスト10個ぜんぶ作る | ◎ | リクエスト＝コメント欄の設計と直結 |
| セキュリティ | （各種） | — | **やらない**（上記） |

**両輪でいく**: 大衆需要側（[genre-crossover](../design/genre-crossover.md)：平成・心理・恋愛・雑学）と、
IT実験側（ここ）。どちらも「これ、AIと作ったらどうなる？」に収まる。
これで「AI開発専門チャンネル」よりずっと大きいところを狙える。
