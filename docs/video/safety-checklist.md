# 出す前に必ず通す（映り込みと権利）

**画面収録は、映したかったもの以外も全部映っている。**
撮影中に気をつけるだけでは漏れる。**編集の工程として機械的に通す**ためのリスト。

撮影中の注意は [収録レギュレーション](../guides/収録レギュレーション.md)、
ゲームそのものの権利は [rights-and-originality.md](../design/rights-and-originality.md)。

---

## 1. 映り込みを機械で洗い出す

目視だけに頼らない。**まず走らせて、候補を出してから見る。**

```bash
cd video
node scripts/scan-risk.mjs <画面収録.mov> --contact
```

出るもの：

| 検出 | 何を見ているか |
|---|---|
| 別ウィンドウ | 想定と違う配色が画面の広い面積を占めるフレーム |
| デスクトップ／Dock | 壁紙の色が広く出るフレーム |
| メニュー展開・通知 | 画面上部に半透明の矩形が出るフレーム |
| 全画面の切り替わり | 前後フレームの差が大きい箇所 |

**候補は必ず人が見る。** 機械は「怪しい」までしか言えない。

### 見つけたら EDL に書き写す（ここが肝）

候補一覧を眺めて「気をつけよう」で終わらせない。**必ず落ちる。**
実際、001 の制作中に `scan-risk` は `47:38→47:44` を候補に挙げていたのに、
そのまま公開の場面の素材に使ってしまい、レンダリング後の確認で見つかった
（アドレスバーの履歴に個人の検索語と住所が出ていた）。

危ないと判断した区間は EDL の `risks` に書く。

```json
"risks": [
  { "src": "screen", "from": 2842, "to": 2866,
    "why": "アドレスバーの履歴に個人の検索と住所が出ている",
    "crops": ["browser", "full"] }
]
```

`extract.mjs` が **切り出そうとしている区間とぶつかったら止める**。
`crops` を書くと、その切り出しにだけ効く（「ブラウザ側にだけ映っている」危険で
同じ時刻のターミナル側まで使えなくなるのを防ぐ）。

**目で見るのは1回でいい。書き写しておけば、あとは機械が毎回見張る。**

## 2. 消す判断（迷ったら消す側に倒す）

| 見つかったもの | 対応 |
|---|---|
| **他プロジェクトの作業内容が読める** | **区間ごとカット**。ぼかしで済ませない |
| 他社・他案件のファイル名／URL | カット、または画面を寄せて枠外に出す |
| 個人名・デバイス名（Bluetooth 等） | 寄せて枠外に出す |
| 通知バナー | その数秒だけ差し替えるか、寄せて隠す |
| デスクトップ・Dock | 寄せて枠外に出す |
| 本番以外の URL（local / staging） | 寄せて枠外に出す |
| ブックマークバー・タブ一覧 | 寄せて枠外に出す |

**「ぼかせばいい」と考えない。** ぼかしは外せる／解像度によっては読める／
そもそも「隠したものがある」と見えること自体が良くない。**寄せるかカットが基本。**

## 3. 既存作を下敷きにした回（いちばん事故りやすい）

[rights-and-originality.md](../design/rights-and-originality.md) は
**「公式の画像・音源・コードは、いかなる形でも持ち込まない」**と決めている。
これは**ゲームだけでなく動画にも効く**。

### 撮影中に必ず起きること

調べながら作ると、**検索結果・App Store・SNS・攻略記事が画面いっぱいに映る**。
そこには原作のスクリーンショット・ロゴ・タイトルが入っている。撮影中は避けられない。

### だから編集でこう処理する

**言及と使用は別**（[rights-and-originality.md](../design/rights-and-originality.md) §言及と使用）。
「◯◯みたいな」「◯◯風」とタイトル・テロップで言うのはよい。出さないのは**元作品の表現**のほう。

| ❌ 出さない | ⭕️ 代わりに出す |
|---|---|
| 検索結果の画面 | **ターミナルに流れているレビュー本文**（自分たちの画面） |
| 原作のスクリーンショット | **自作の線画で、仕組みだけ**を図示 |
| 原作のロゴ・画像 | 出さない（「◯◯みたいな」という言及テロップはよい） |
| ストアページ・動画サイト | 出さない |

**AIが読んでいるテキストは自分たちの画面なので、そのまま使える。**
むしろ「AIが当時のレビューを読んで不満点を2つ見つけた」という画のほうが、
検索結果を映すより中身がある。

### 自作図解の線引き

- 仕組み（上下に動かして穴を通す）を**棒と丸だけ**で描く
- 原作の配色・キャラ・UIを再現しない
- 「◯◯という作品」と名指ししない。**「当時こういう遊びがあった」**と言う

## 4. 商標・実在の商品

制約の現物（カップ・ポテト）が映るのは問題ない
（[rights-and-originality.md](../design/rights-and-originality.md) §商標）。

- ⭕️ 飲み物のカップが映る。飲み干す
- ⭕️ 「ソイラテ1杯ぶん」と言う
- ❌ ロゴを画面の主役にする・サムネの中心に置く
- ❌ ゲーム内に商品名やロゴを持ち込む

## 5. 出す直前のチェック

- [ ] `scan-risk.mjs` の候補を全部見た
- [ ] 他プロジェクトが読める区間は**カットした**（ぼかしで済ませていない）
- [ ] 原作の画像・ロゴ・タイトルが1フレームも入っていない
- [ ] 題材への言及が「〜みたいな」「〜風」の形になっている（誤認させる書き方をしていない）
- [ ] `meta.inspiration` の内容と、動画で言っていることが食い違っていない
- [ ] 通知・メニュー・Dock・ブックマークが映っていない
- [ ] URL が本番のものだけになっている
- [ ] **AIが確かめていないことを「確認しました」と言っていない**

## 実績（001 ぬいみち回で見つかったもの）

同じことは毎回起きる。**次回はここを先に潰す。**

| 画面収録の時刻 | 見つかったもの | 対応 |
|---|---|---|
| 0:22〜0:30 / 0:38〜1:05 | 他プロジェクト4件の作業内容が全部読める（別ターミナル） | **全カット** |
| 2:00〜13:40 | 原作の公式スクショ・ロゴ・ストア・SNS | **画を使わず、ターミナル＋自作図解に差し替え** |
| 11:20 | アプリ一覧（Launchpad） | カット |
| 25:40 | 別アプリ（他プロダクト） | カット |
| 28:00 | デスクトップ・Dock | 寄せて枠外へ |
| 31:40 | 社内 URL の候補表示 | 寄せて枠外へ |
| 45:00〜45:20 | Bluetooth のデバイス名 | 寄せて枠外へ |
| **47:22〜47:46** | **アドレスバーの履歴に個人の検索語と住所** | **使う区間をずらした（いちばん危なかった）** |
| 47:54〜48:03 / 48:22〜48:29 | 通知バナー（Slack） | 使う区間をずらした |

いちばん危なかったのは `47:22〜47:46`。**「本番URLを開く」という、動画でいちばん見せたい場面**に
アドレスバーの履歴が重なっていた。見せたい場面ほど、そこしか素材が無いので押し通しがちになる。
ずらせる素材が近くにあるか、先に確かめること。

**次の収録では**、撮る前に別ターミナルを閉じる・通知を切る・ブックマークバーを隠す。
それでも起きるので、このリストは毎回通す。
