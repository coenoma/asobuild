# 音の設計

**音は飾りではなく、いま何が起きているかの合図。**
同じ出来事にはいつも同じ音を当てる。そうすると、見ている人は画を見なくても状況が分かるようになる。

## 🔴 音源は外から持ってこない

効果音もジングルも **`video/scripts/sfx.mjs` の中で合成する**。理由は2つ。

1. **このリポジトリは PUBLIC。** よくある「動画での使用は無料（要クレジット）」の楽曲も、
   **音源ファイルそのものの再配布は禁止**なことが多い。リポジトリに置く＝再配布になる
2. 買ってきた音を混ぜると、**そこだけ質感が変わって浮く**。ゲームの音（`src/arcade/sfx.ts`）と
   同じ矩形波で作れば、番組全体の音が最初から揃う

```bash
cd video
node scripts/sfx.mjs        # public/sfx/*.wav を作り直す
```

外部の曲をどうしても使いたくなったら、**リポジトリには入れず**、書き出しのときだけ
手元のファイルを混ぜる（そして概要欄にクレジットを書く）。**BGMがこの形**。

## BGM（外の曲。リポジトリには置かない）

置き場所は `video/bgm/`。**`.gitignore` に入れてある**ので、コミットされない。
無ければ黙って鳴らさずに書き出せるので、他の人が clone しても止まらない。

```
video/bgm/main.mp3    下に敷く曲
video/bgm/ending.wav  締めの曲
```

EDL の `meta` に、**どれを・どれくらいの大きさで**鳴らすかを書く。

```json
"bgm":       { "file": "bgm/main.mp3",   "peakDb": -32 },
"endingBgm": { "file": "bgm/ending.wav", "peakDb": -8, "at": 318.53 }
```

- 大きさは**頂点を何dBにするか**で指定する。元の音量はまちまちなので、
  書き出しのときに実測してから差を当てる（`peakDb` だけ決めればよい）
- 下に敷く曲は **-43dB**。**かなり小さい。** 「気配があるかな」くらいで合っている
  （-32 から始めて、聴きながら 5dB ずつ下げてここに落ち着いた。
  この番組はターミナルの音とゲーム音が主役なので、曲が前に出ると邪魔になる）。
  ループして全体を覆い、締めの曲に入る 2.5秒前から消える
- **音量を決めるときは 5dB 刻みで動かす。** 1dB は聴き分けられず、往復するだけになる
- 締めの曲は **-8dB**。**最後の一言（「ではでは、また次の動画で」）が終わった直後**から鳴らす。
  `at` は絶対秒。最後の章の長さは、曲が鳴りきる長さに合わせる
- 001 で使っているもの: `Let's!` / `Next Time`（JTLXq）。
  **概要欄にクレジットを書くこと。** 曲を変えたらここも書き換える

## 仕上げの音量（ラウドネス）

**YouTube は -14 LUFS 基準で「下げる」ことはするが「上げてくれない」。**
うちの書き出しは素のままだと -20 LUFS 前後で、**他の動画より一段小さく聞こえていた**
（数万再生クラスとの、測れる差）。

`npm run build` の最後に `scripts/master.mjs` が自動で通る:
- 2回測って線形に当てる（声・BGM・効果音のバランスは変えずに全体を持ち上げる）
- 目標 **-14 LUFS / 頂点 -1 dBTP**。映像は再圧縮しない
- 出力は `out/<slug>-master.mp4`。**公開に使うのはこれ**

## 音の一覧（意味を1対1で固定する）

| 音 | 意味 | 置く場所 |
|---|---|---|
| **`title`** | **番組の名刺。** 毎回まったく同じものを使う | タイトルカード |
| `outro` | 終わった | 締めのカード |
| `swipe` → `stampHit` | 場面が変わる | 経過時間の判子（`timeStamp`）の直前と頭 |
| `reveal` | ここを見て | `spot`（枠＋矢印） |
| ~~`type`~~ | 打鍵。**使わない** | 一度入れたが「ピピピピ」と鳴ってナレーションの邪魔になった（001のFB）。音は残してあるが置かない |
| `tap` | 遊びはじめ | プレイの頭 |
| `score` | 点が入った・結果が出た | 加点・結果画面 |
| `best` | 記録更新・できた | 自己ベスト／新しい版ができた |
| `over` | 終わった・まずい | ゲームオーバー／時間が押している |
| `jingleOver` | 時間切れ | タイムアップの判子 |
| `jingleGoal` | 公開した | 本番URLを開く |
| `sting` | **ここから結論** | 「さて、結論です」の直前。**1本で1回だけ** |

**同じ意味に違う音を当てない。** 迷ったら、この表に無い音は鳴らさない。

## 鳴らしすぎない・重ねない

一度これで失敗している。**同時に鳴らすほど「わちゃわちゃして気持ち悪い」**（001で3回指摘された）。

- **同時に鳴るのは最大3音まで。** ジングルの中の和音も含めて数える
  （タイトルコールは 低音＋2音。最初は5音鳴っていて濁っていた）
- **判子には「風切り→一撃」の2つだけ。** ほかの音を同じ場所に置かない。
  章の頭で前置きの間が取れないときは、風切りを鳴らさず一撃だけにする
- **同じ音を連打しない。** 打鍵の4連打は「ピピピピ」と聞こえて邪魔だった
- **`sting` は1本に1回。** 何度も使うと「ここぞ」が無くなる
- 効果音どうしの間隔は 0.3秒以上あける
- 音量は 0.55〜0.95 の範囲。既定は 0.85
- 目安は **1本で40音前後**（5分で8秒に1回）。それ以上は多い

## タイトルコールの作り

`title` は番組の記号なので、**変えない**。中身は次の4段。

1. 低い土台（C3）を伸ばす — 上の音が軽く聞こえないように
2. 駆け上がり4音（G4 → C5 → E5 → G5）
3. 着地の和音（C6・E6・G6）を伸ばす ← ここが「アソビルド」
4. 上のきらめき（E6 → G6 → C7）で余韻

同時発音は**3つまで**（当時のケータイに合わせている）。

## 音を足したくなったら

1. まず「その音は何を意味するか」を1行で言えるか確かめる。言えないなら足さない
2. `sfx.mjs` の `SOUNDS` に足す。**ゲームの `sfx.ts` にある音は、そちらと定義を合わせる**
3. この表に行を足す
4. `node scripts/sfx.mjs` で書き出して、**人が聴く**（AIは音の良し悪しを判断できない）

見本をまとめて聴くには:

```bash
cd video/public/sfx
ffmpeg -f lavfi -i anullsrc=r=48000:cl=mono -t 0.7 silence.wav
# 聴きたい順に concat して1本にする（docs のこの節の手順）
```
