# 構成の作り方

**章立ては固定しない。毎回、撮った人の心情の流れがそのまま構成になる。**

なぜそうするのかは [video-doctrine.md](./video-doctrine.md) §0.5。
編集側できれいな主題を作ると、**本人が言っていないことを本人の声で言わせる**ことになる。

文字の決まりは [telop-rules.md](./telop-rules.md)。

---

## 尺は7分を上限にする

| 状況 | 尺 |
|---|---|
| **チャンネルが知られていない間** | **7分**（凝縮する） |
| 見てくれる人がついてから | 10〜14分まで伸ばしてよい |

**初見の人は、知らない人の開発を14分も見ない。**
素材が49分あっても7分に落とす。落ちないのは、心情に紐づいていない素材が残っているから。

## 手順

### 1. 撮った人に心情を書き出してもらう（これが無いと始めない）

出来事ではなく、**その時どう思ったか**を10〜20行。順番だけ守る。整える必要はない。

```
まずはたくさんの情報をぶっこんでみよう
なんか考えてる？
長い・・・もっと補足情報をぶっこみまくろう
糸通しについてももう少し思い出すか
あーこんなだったな
もっともっとぶっこむぞ
時間切れじゃん？
あ、なんかできてる！
それっぽいそれっぽい笑
けど時間切れ・・・まあここから少しだけブラッシュアップするか
よーしブラッシュアップだ！
いいねいいね
さいこう！はまる！
結論？急に動くのができたし、元のより面白いかも！？
おそろしや・・・
ここからあなたも遊べるよ
```

**編集する側（AIを含む）がこれを代筆しない。** 素材から推測もしない。
無いなら聞く。聞けないなら作らない。

### 2. 隣り合う心情をまとめて章にする

上の例なら、こうなる（001回の実際）。

| 章 | 心情 | 尺 |
|---|---|---|
| `hook` | — | 18 |
| `throw` | ぶっこむ／考えてる？／長い | 52 |
| `recall` | 思い出すか／あーこんなだった | 42 |
| `more` | もっとぶっこむ／時間切れじゃん？ | 38 |
| `appeared` | あ、なんかできてる！ | 40 |
| `itsuppoi` | それっぽい笑／全然だめじゃん | 40 |
| `timeup` | けど時間切れ | 30 |
| `brushup` | よーしブラッシュアップだ | 60 |
| `best` | いいねいいね／さいこう、はまる | 40 |
| `scary` | 元のより面白いかも／おそろしや | 38 |
| `end` | 遊んでね | 22 |

**章の名前は心情の言葉にする。** 「検定」「実装」のような工程名にしない。
工程名にした瞬間、構成が「作り方の説明」に戻る。

### 3. 各章に、その心情が伝わる画を当てる

素材から探す。**無ければ章を短くする。** 別の主張で埋めない。

### 4. 心情に無いものは入れない

面白い素材でも、その時そう思っていなかったなら外す。
リポジトリの仕組み（面白さゲート等）も、**その時に触っていたなら1ビートだけ**。主題にしない。

## どの章にも共通する作り

### フック（最初の15〜20秒）

```
0:00  いちばん良い瞬間を2秒（音つき・結果は出さない）
0:02  黒コマ 0.25秒
0:03  制約の現物（カップ）＋ 何を頼んだか
0:07  頼んでいる画面 ＋ 実験の宣言
0:10  全景 ＋ 賭けの条件（1文字も書かない）
0:14  タイトル
```

**結果を出さない。** スコアも、公開できたかどうかも見せない。

### 底を中盤に置く

心情の流れには必ず底がある（「時間切れじゃん？」「全然だめじゃん」）。
**そこが動画の折り返し。** 前半で解決すると後半を見る理由が消える。

### 締め（最後の20秒）

遊べる場所 → 高評価・チャンネル登録 → リクエスト → 最高記録をコメントで。
[video-doctrine.md](./video-doctrine.md) §6。

## 作業の流れ

```bash
cd video          # 以下すべてここで実行する

# 1. 映り込みを機械で洗い出す（人が全部見て、危ないものは EDL の risks へ書き写す）
node scripts/scan-risk.mjs <画面収録.mov> --contact

# 2. 開発ログを動画の時刻に変換する（何分何秒に何が起きたか）
node scripts/timeline.mjs --rec-start "2026-08-12T16:32:09+09:00"

# 3. 心情の箇条書き × 素材の地図 → edl/<slug>.json を書く（手作業はここだけ）
# 4. 必要な区間だけ切り出す（先に EDL の検査が走る）
node scripts/extract.mjs edl/<slug>.json

# 5. 確認して書き出す
npx remotion studio
npx remotion render src/index.ts Episode out/<slug>.mp4
```

書体と効果音は最初の1回だけ（`node scripts/fonts.mjs` / `node scripts/sfx.mjs`）。

**手打ちするのは EDL の1ファイルだけ**にする。ゲートの合否や落ちた項目名は
`.live/status.jsonl` から引く（`timeline.mjs`）。手で書き写すと必ずずれる。

## ナレーションは後から乗せる

**映像を先に完成させ、声はあとで足す。**

- 台本は**箇条書きと尺の目安**だけ渡す（一字一句の原稿を作らない）
- 話す人は原稿に縛られず、自分の言葉で喋る
- 上がってきた音源に合わせて、**EDL の章の尺（`dur`）を調整して描き直す**

だから EDL はデータで持つ。**声が来てから直せることが前提**の作り方にしてある。

テロップは声に依存させない。**画面に映っている事実と、その時の心情だけ**を書くので、
喋りが変わってもテロップは作り直さなくてよい。
