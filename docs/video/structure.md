# 構成の作り方

**章立ては固定しない。毎回、撮った人の心情の流れがそのまま構成になる。**

なぜそうするのかは [video-doctrine.md](./video-doctrine.md) §0.5。
編集側できれいな主題を作ると、**本人が言っていないことを本人の声で言わせる**ことになる。

文字の決まりは [telop-rules.md](./telop-rules.md)。

---

## 尺とテンポ

**7分は上限であって、目標ではない。埋めない。**
初見の人は、知らない人の開発を長くは見ない。素材と心情が持つ長さで終わる。

### タイミングの物差し（ここが気持ちよさに直結する）

| | 目安 |
|---|---|
| **反応の行は、出来事の何秒あとか** | **0.3〜1.2秒あと**。同時・先回りは「予知」に見えて気持ち悪い |
| まだ起きていないことを先に言う | **禁止**。「一覧に出てる！」の直後に出てくると嘘に見える |
| 読ませる画（本文・依頼文） | **動かさない**。寄って、止めて読める大きさにする |

機械で見張れる。`node scripts/sync-check.mjs edl/<slug>.json`（[edit-checklist.md](./edit-checklist.md) §1）。

## 節目には判子を打つ（のっぺりさせない）

章が変わるだけでは切れ目にならない。**画を止めて経過時間を大きく出す**（`timeStamp`）。
制限時間が企画なので、時間の表示は飾りではなく本体。1本で4〜6回。
打つ場所は「できた／時間切れ／作り直し開始／まだ遊んでる／ぜんぶ終わった」。

## 決めの瞬間（punch）── ここが見せ場だ、と編集が肩を叩く

バラエティの「ズーム→静止→効果音」。ゲーム側 feel.ts のヒットストップ
（当たった瞬間、世界が一瞬止まる）の、動画への移植でもある。
EDL に1行書くだけ（layer type `punch`。クリップ内の何秒の画で止めるかを `frame` で指す）。

```json
{ "type": "punch", "at": 12.0, "dur": 0.6, "clip": "best-560", "frame": 3.2,
  "zoom": 1.4, "origin": [0.5, 0.35] }
```

- **使うのは3種だけ**: 記録更新（「できた」）／初めて動いた／即死・事故
- **1本に2〜3回まで。** 毎回やると「ここぞ」が消える（sting が1本1回なのと同じ）
- `origin` は決めたいもの（スコア表示など）の位置。真ん中で寄っても何も決まらない
- 覆っているあいだも下の映像は進む（戻さない・巻かない）。**dur は 0.4〜0.8秒**。
  結果画面のような静止した画に当てると、切れ目は見えない
- どこに打つかは、**アテレコで声が上がった瞬間が教えてくれる**
  （[atereco.md](./atereco.md)。声が先、演出が後）

## テンポの物差し（ここから外れたら遅い）

| もの | 長さ |
|---|---|
| テロップ1枚 | **2〜3.5秒** |
| 1つの画（ショット） | **3〜8秒** |
| 章タイトル | 1.8秒 |
| 切り替えの黒 | 0.25秒 |
| 見せ場の黒（言葉だけ聞かせる） | 1本の動画に2回まで、各7〜11秒 |

> 実測（001回）: 1画10秒超・テロップ4〜6秒で組んだら
> **「全体的にゆっくり。この分量なら2倍速でいい」と差し戻し**になった。
> 同じ素材を上の物差しで組み直したら 7:00 → 4:39 になり、ビート数はむしろ増えた。

**この物差しで組んで7分を超えるなら、素材を削る**（心情に紐づいていないものが残っている）。
7分に届かないのは問題ではない。

## 手順

### 1. 撮った人に心情を書き出してもらう（これが無いと始めない）

出来事ではなく、**その時どう思ったか**を10〜20行。順番だけ守る。整える必要はない。

```
まずはたくさんの情報をぶっこんでみよう
なんか考えてる？
長い・・・もっと補足情報をぶっこみまくろう
糸通しについてももう少し思い出すか
あーこんなだったな
もっともっとぶっこむぞ
時間切れじゃん？
あ、なんかできてる！
それっぽいそれっぽい笑
けど時間切れ・・・まあここから少しだけブラッシュアップするか
よーしブラッシュアップだ！
いいねいいね
さいこう！はまる！
結論？急に動くのができたし、元のより面白いかも！？
おそろしや・・・
ここからあなたも遊べるよ
```

**編集する側（AIを含む）がこれを代筆しない。** 素材から推測もしない。
無いなら聞く。聞けないなら作らない。

**書き出した心情は EDL の `chapters[].mood` に入れる。**
絵コンテにそのまま出るので、あとから「この章は何の気持ちだったか」を見失わない。

### 2. 隣り合う心情をまとめて章にする

上の例なら、こうなる（001回の実際）。

| 章 | 心情 | 尺 |
|---|---|---|
| `hook` | — | 18 |
| `throw` | ぶっこむ／考えてる？／長い | 52 |
| `recall` | 思い出すか／あーこんなだった | 42 |
| `more` | もっとぶっこむ／時間切れじゃん？ | 38 |
| `appeared` | あ、なんかできてる！ | 40 |
| `itsuppoi` | それっぽい笑／全然だめじゃん | 40 |
| `timeup` | けど時間切れ | 30 |
| `brushup` | よーしブラッシュアップだ | 60 |
| `best` | いいねいいね／さいこう、はまる | 40 |
| `scary` | 元のより面白いかも／おそろしや | 38 |
| `end` | 遊んでね | 22 |

**章の名前は心情の言葉にする。** 「検定」「実装」のような工程名にしない。
工程名にした瞬間、構成が「作り方の説明」に戻る。

### 3. 各章に、その心情が伝わる画を当てる

素材から探す。**無ければ章を短くする。** 別の主張で埋めない。

**撮った人が「ここ使いたい」と言った場所は [各回の footage-notes.md](../episodes/) に時刻つきで貯める。**
言われたその場で書く。書かないと消える。

### 4. 心情に無いものは入れない

面白い素材でも、その時そう思っていなかったなら外す。

**リポジトリの仕組み（面白さゲート・共通シェル・公開前チェック等）は、1ビートも入れない。**
道具の名前を出した瞬間に「内輪の解説」になる（[video-doctrine.md](./video-doctrine.md) §0）。
同じ場面を使いたいなら、**仕組みの名前を出さずに、そのとき思ったことで言い換える**。

> ❌「検定に落ちた」「12項目ぜんぶ緑」
> ⭕️「まだうまく通らない」「お？いけてそう？」

## どの章にも共通する作り

### フック（最初の15〜20秒）

```
0:00  いちばん良い瞬間を2秒（音つき・結果は出さない）
0:02  黒コマ 0.25秒
0:03  制約の現物（カップ）＋ 何を頼んだか
0:07  頼んでいる画面 ＋ 実験の宣言
0:10  全景 ＋ 賭けの条件（1文字も書かない）
0:14  タイトル
```

**結果を出さない。** スコアも、公開できたかどうかも見せない。

### 底を中盤に置く

心情の流れには必ず底がある（「時間切れじゃん？」「全然だめじゃん」）。
**そこが動画の折り返し。** 前半で解決すると後半を見る理由が消える。

### 場面転換のローディング（汎用パーツ）

場面が大きく飛ぶとき（開発時間が飛ぶ・工程が変わる）に、EDL のレイヤーで入れられる。

```json
{ "type": "loading", "at": 0, "dur": 1.2, "note": "つぎ：ブラッシュアップ" }
```

ゲームの「よみこみ中…」画面と同じ様式（`video/src/components/Loading.tsx`）。
見本は `npx remotion still src/index.ts Loading out/loading.png`。
**連発しない。** 転換のたびに入れるとそれ自体がテンポを削る。1本に1〜2回まで。

### 締め（最後の20秒）

遊べる場所 → 高評価・チャンネル登録 → リクエスト → 最高記録をコメントで。
[video-doctrine.md](./video-doctrine.md) §6。

## 作業の流れ

```bash
cd video          # 以下すべてここで実行する

# 1. 映り込みを機械で洗い出す（人が全部見て、危ないものは EDL の risks へ書き写す）
node scripts/scan-risk.mjs <画面収録.mov> --contact

# 2. 開発ログを動画の時刻に変換する（何分何秒に何が起きたか）
node scripts/timeline.mjs --rec-start "2026-08-12T16:32:09+09:00"

# 3. 心情の箇条書き × 素材の地図 → edl/<slug>.json を書く（手作業はここだけ）
# 4. 必要な区間だけ切り出す（先に EDL の検査が走る）
node scripts/extract.mjs edl/<slug>.json

# 5. 絵コンテを出して、構成を相談する（映像を待たずに詰められる）
node scripts/storyboard.mjs edl/<slug>.json > ../docs/episodes/<slug>/storyboard.md

# 6. 確認して書き出す
npx remotion studio
npm run build -- <slug>   # 省略で最新の回
```

書体と効果音は最初の1回だけ（`node scripts/fonts.mjs` / `node scripts/sfx.mjs`）。

**手打ちするのは EDL の1ファイルだけ**にする。ゲートの合否や落ちた項目名は
`.live/status.jsonl` から引く（`timeline.mjs`）。手で書き写すと必ずずれる。

## ナレーションが背骨（通しでずっと喋っている）

**この動画は、効果音と映像だけの時間がほとんど無い。** ナレーションが最初から最後まで走り、
字幕（全文）がそれに付く。だから作る順番はこうなる。

```bash
# 1. 原稿を書く（voice/<slug>.json。行ごとに at=章内の秒 を持つ）
#    声の決まりは voice-and-script.md（ぼく・ですます・1行20字まで・感情は言い切り）
#    反応の行には after を、読ませる行には reads:true を書く（sync-check が見張る）
# 2. 行ごとに合成して、長さを実測（既定はずんだもん）
node scripts/voice.mjs edl/<slug>.json --synth
#    → 行が次の行に食い込むと△が出る。原稿を削るか at をずらす

# 3. 字幕テロップを EDL に書き込む（gen:true の層だけ入れ替え。手書きの層は触らない）
node scripts/voice.mjs edl/<slug>.json --apply

# 4. 描画して、声を混ぜる（映像はコピーなので mux は数秒）
npm run build -- <slug>   # 省略で最新の回
node scripts/voice.mjs edl/<slug>.json --mux      # → out/<slug>-voiced.mp4
```

**原稿が、声と字幕の両方の源。** だから声と字幕はずれようがないし、
文言を直すのは原稿1ファイルだけでよい。

### 確認用の声 → 本命の声

| 段階 | 声 | やり方 |
|---|---|---|
| **確認用** | VOICEVOX（ずんだもん） | 上の手順そのまま |
| **本命** | 撮った人の声 | 章ごとに録った wav を `voice/<slug>/human/<章ID>.wav` に置く。**--mux がそちらを優先** |

本命に切り替えたら、人の声の間に合わせて**原稿の `at` を直し、`--apply` → 描画**で字幕が追従する。
**本命は読み上げではない**——動画を見ながら自由に喋った画面収録が本命で、声に映像を合わせ直す。
録り方から本ちゃん化までは [atereco.md](./atereco.md)（原稿は撮る前の「予定」で、あとで実際の言葉に書き直す）。
