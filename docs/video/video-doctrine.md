# 動画の原則

**このリポジトリは「動くものを作る」だけでは終わらない。**
撮った素材を、**遊んでいない人が最後まで見る1本**に組み立てるところまでが仕事。

ゲームの面白さの原則が [fun-doctrine.md](../design/fun-doctrine.md) に固定してあるのと同じで、
**毎回考えるのは「今回どう撮れたか」だけで、「どう見せるか」は毎回同じ手順を踏む**ためのもの。

作るときの型は [structure.md](./structure.md)、文字の決まりは [telop-rules.md](./telop-rules.md)。

---

## 0. これは「実験」の記録である

**この番組は、作品の発表でもノウハウの共有でもない。**

> **「AIに◯◯って頼んでみたら、どうなるのか」を、そのまま出す。**

だからタイトルも中身も「実験してみた」の形をとる。
「うまく作りました」「こうすれば作れます」に寄せた瞬間、この番組ではなくなる。

### 🔴 リポジトリの工夫は、動画に一切出さない

**これは恒久ルール。** 面白さゲート・共通ランタイム・カンペ・公開前チェック——
このリポジトリが持っている仕組みは、**作るための道具であって、番組の中身ではない**。

| 出さない | なぜ |
|---|---|
| 面白さゲート／12項目の検定 | 見ている人には「謎の内輪の話」。何も伝わらない |
| ボットに数百回遊ばせている話 | 同上。すごさが伝わる相手が狭すぎる |
| 共通シェル・雛形・登録簿の仕組み | 作り方の解説になる。番組は実験の記録 |
| 公開前チェック・playtest の記録 | 同上 |

**出してよいのは、画面に起きた事実と、そのとき思ったことだけ。**
「検定に落ちた」ではなく「まだうまく通らない」。**仕組みの名前を出さずに言い換える。**

> やらかした実例（001回・2版目）: ブラッシュアップの章を「面白さゲートに落ちる→直す→12項目ぜんぶ緑」で
> 組んだが、撮った本人は**そんなことは一度も思っていなかった**。
> 実際に思っていたのは「めちゃいい」「あれ、当たっても死なない？」だった。

### 出すもの・出さないもの

| 出す | 出さない |
|---|---|
| 雑に投げたところ | きれいに設計したところ |
| 待たされたところ・詰まったところ | 順調に進んだところだけ |
| だめだったところ、そのときの本音 | 結果から逆算した「学び」 |
| **「なんかできてた」という驚き** | **「こうやって作りました」という解説** |
| 画面に起きた事実 | リポジトリの仕組み・道具の名前 |

制約（飲み物1杯）は、この実験に**締め切りを与えるためのもの**。
残量が画面に映ることで「間に合うのか」が絵になる。それ以上の意味を持たせない。

## 0.5 構成は「出来事」ではなく「心情の流れ」で作る

🔴 **ここがいちばん間違えやすい。実際に1本まるごと作り直した。**

素材を見ると、編集する側は**きれいな主題を見つけたくなる**。
「動くこと≠面白いこと」「機械が決められる線と、人にしか決められない線」——
そういう話は素材から**いくらでも作れてしまう**。作れてしまうが、**それは撮った人が思っていたことではない。**

やってしまった失敗（001回・初版）:

> 編集側が「動くこと≠面白いこと」という主題を発明し、
> 面白さゲートを中心に据えた11章のドキュメンタリーを組んだ。
> 撮った本人の実際の心情は「雑に投げまくったら、時間切れギリギリで何かできてた」で、
> **ゲートのことは一度も思っていなかった。**

### だから手順を固定する

1. **撮った人が、その時どう思っていたかを箇条書きで書き出す**（10〜20行。順番だけ守る）
2. **その箇条書きを章にする。** 出来事ではなく心情が章の単位
3. 各章に「その心情が伝わる画」を素材から探して当てる
4. **箇条書きに無いものは入れない。** 面白い素材でも、その時そう思っていなかったなら外す

心情の箇条書きが無いまま編集を始めない。**無いなら、撮った人に聞く。**

> 実例（001回）:
> なげる → 考えてる？ → 長い、もっと投げよう → 思い出して足す → まだ投げる
> → 時間切れじゃない？ → お、できてる！ → それっぽい笑 → でも時間切れ
> → よーしブラッシュアップだ → いいねいいね → さいこう、はまる
> → 雑に投げただけなのに元より面白いかも → おそろしや → あそんでね

### 編集する側（AIを含む）へ

**思想を足さない。** 主題を発見したくなったら、それは自分の欲であって素材の要求ではない。
リポジトリのドキュメントに書いてある原則（面白さゲート等）は**作るときの道具**であって、
**動画の主題ではない**。混同すると、本人が言っていないことを本人の声で言わせることになる。

## 1. 誰に向けて作るか

優先順に3層。**1つ目だけを狙うと母数が足りず、2つ目だけを狙うと薄くなる。**

| # | 層 | 刺さり方 | 動画のどこで掴むか |
|---|---|---|---|
| 1 | AIコーディングを触っている／気になっている人（20〜40代） | 「自分の環境でも同じことができるのか」 | ターミナルが実際に動いている画 |
| 2 | ガラケー・Flash ゲーム世代（30〜45歳） | 「あー、これ知ってる」 | **題材**。ここが一般層への入口 |
| 3 | 個人開発・ゲーム制作の人 | 「雑な依頼で、どこまで行くのか」 | 詰まって直しているところ |

**題材選びは2層目のためにある。** 宇宙やドラゴンではなく、ハンコ・糸通し・傘。
[retro-style.md](../design/retro-style.md) §4 が「題材が地味なほど当時っぽい」と言っているのは、
遊ぶ人のためだけでなく、**動画が一般層に届くため**でもある。

## 2. どんな気持ちでクリックしてもらうか

**サムネイルとタイトルの仕事は「結果を見たくさせる」ことだけ。**
面白さを説明しない。完成度を自慢しない。

### 守ること（サムネの型はシリーズで固定する）

型: **AI名バッジ ＋ 決定的瞬間のゲーム画面 ＋ 制約の実物 ＋ 7文字級の言葉1つ**。
毎回同じレイアウトにする。**型の反復が「また来た」を作り、登録につながる**（実測: バズ単発は登録に変換されない）。

| 決まり | 理由 |
|---|---|
| **AI名（Claude Code）を文字バッジで大きく** | 視聴者は「どのAIがやるか」を配役として見ている。公式ロゴ画像は使わない（誤認を避ける） |
| **ゲーム画面はプレイ途中の決定的瞬間** | 結果（最終スコア・成否・完成の宣言）は出さない。結果が見えたら押す理由が消える |
| **制約の現物を写す** | カップ・ポテト。物理モノがクリックを作る（実写系サムネが上位という実測） |
| **文字は1メッセージ・大きい行は7文字級** | 2つ置くと読まれない |
| **顔は入れてよい。主役にしない** | 人がやっていると分かる程度 |

### 最初の3秒 ── 「？」から始める

説明やあいさつから入らない。視聴者は**タイトルの約束を見てクリックしている**ので、
冒頭の仕事は説明ではなく**約束とのズレ**を見せること。型は2拍:

> 「AIに『◯◯』を頼んだら」→ **謎の途中経過が動く** →「……◯◯？」→ 本編

- 見せてよいのは**謎**のほう（途中経過の変な姿）。**完成品と結果の数字は出さない**
- 「？」だけの画にしない。**約束（題材名）と接続**しないと、ただのクイズになって意味が立たない
  （001で実際にやり直した）
- 声はいらない。効果音1発とテロップ2枚。**4秒以内**

### タイトルの型

> **［制約］で、AIは［題材］を作れるのか**

3つの部品でできている。調査の裏付けは [research-notes/2026-08-13-youtube.md](./research-notes/2026-08-13-youtube.md)。

| 部品 | 例 | なぜ |
|---|---|---|
| **制約** | ソイラテ1杯で／記憶だけで | 何が賭けられているか |
| **題材**（知名度が命） | 糸通しみたいなゲーム | **題材の知名度が再生数の最大変数**（同一チャンネル内で50倍差の実測） |
| **疑問形／結果の引き** | 作れるのか／〜したら | **疑問形は「作ってみた」の7倍伸びた実測がある**（同一作者・同一題材） |

- ⭕️ 「ソイラテ1杯で、AIは"糸通しみたいなゲーム"を作れるのか」
- ⭕️ 「AIに『糸通しみたいなゲーム作って』って雑に頼んでみた」
- ❌ 「AIでゲームを作ってみたら神ゲーができたwww」（結果を書いている・煽りが中身と合わない）
- ❌ 「Claude Codeでミニゲーム開発」（実験に見えない・何が賭けられているか無い）

**題材の言及は「〜みたいな」「〜風」の形にする**（[safety-checklist.md](./safety-checklist.md) §3）。
着想元に触れること自体は誠実さであり、隠さない。ゲーム名・配布物・ロゴには使わない。

## 3. どんな気持ちで見始めてもらうか（0〜15秒）

**離脱がいちばん起きるのはここ。** 15秒で次の3つを全部渡す。

1. **何を頼んだか**（1文）
2. **賭けの条件**（コードは1文字も書かない／飲み干したら終わり）
3. **まだ何もできていない**ことが伝わる画

### 🔴 できたものを冒頭に出さない

完成したゲームが動いている画を冒頭に置くと、**それだけでネタバレになる**。
「どうなるのか」を見たくて押した人に、最初に答えを見せてしまう。

- ❌ 完成したゲームのプレイ画面・スコア・公開できたかどうか
- ⭕️ 制約の現物（カップ）・頼んでいる画面・AIが考えている画面・自分の顔

**動きが要るなら、ターミナルが動いている画を使う。** 中身は分からないが、何かが起きている感じは出る。

> 実装: [structure.md](./structure.md) §フック

## 4. どんな気持ちで見続けてもらうか

見続ける理由は「面白いから」ではなく、**「まだ終わっていないから」**。
終わっていないことを、画面で常に見せ続ける。

### 進行が目に見える（常時）

- **カップの残量** — 減っていくのが見える。これ自体がタイマー
- **経過時間** — 画面の隅に固定

制約は「残り時間が画面に映るもの」ほど強い（[収録レギュレーション](../guides/収録レギュレーション.md)）。
**それは撮影のためだけでなく、編集で使う素材としても効く。**

### 2〜4秒に1回、何かが動く

同じ絵が続くと「止まっている」に見える。テロップが出る・数字が動く・画が替わる——
**どれかが2〜4秒に1回**起きるように刻む（物差しは [structure.md](./structure.md) §尺とテンポ）。

章の単位でも、30〜40秒に1回は状態が変わる（できた・死んだ・時間切れ）。
これはゲート `画面で何かが起きる間隔` の考え方（[broadcast-design.md](../design/broadcast-design.md)）を
**動画そのものに適用したもの**。遊ぶ人に効くものは、見る人にも効く。

**ゆっくり＝丁寧、ではない。** 実際に「全体的にゆっくり」で1本まるごと差し戻しになった。

### いちばん低いところを中盤に置く

心情の流れには必ず**底**がある。「時間切れじゃない？」「全然だめじゃん」。
そこを中盤に置く。前半で解決すると、後半を見る理由がなくなる。

**底は作らない。探す。** 撮った人が実際に落ち込んだところが底。

## 5. 避けること（＝離脱の作り方）

| やってはいけない | 代わりに |
|---|---|
| AIが考えている無音をそのまま置く | 速度を上げる／その間に何を待っているかを出す |
| 同じ絵が10秒以上続く | 寄る・引く・切り替える |
| 説明が2文以上続く | 図解1枚にする |
| 専門用語をそのまま出す | 画面に出た言葉だけを使う |
| 成功だけを並べる | **失敗を必ず入れる**（[broadcast-design.md](../design/broadcast-design.md) §3） |

## 6. 見た人に何を持って帰ってもらうか（最後の20秒）

締めは4つ。**読み上げに頼らず、画面に文字で出す。**

1. **遊べる場所** — 「いま遊べます」＋URL。概要欄にもあると言う
2. **高評価とチャンネル登録** — 素直に頼む。もったいぶらない
3. **リクエスト** — 「これ作ってみて」をコメントで募る。**次回のお題がここから来る**
4. **最高記録** — 「あなたのスコアをコメントで」。遊んだ人が戻ってくる理由になる

3と4があると、コメント欄が**次の企画の材料置き場**になる。
「面白かった」で終わらせず、手を動かせる状態で終わる。

## 7. シリーズとしての戦い方

1本の作り方と別に、**続けるための型**をここに固定する。

- **型は固定して反復する**: タイトルの3部品・サムネのレイアウト・締めの4点セット。
  バズは入口にしかならず、**登録を作るのはシリーズの型の反復**（調査の実測）
- **企画回と本気回の2本立て**: 制約つきの回（この番組の基本）のあとに、
  同じゲームを「制限なしで作り込んだらどうなるか」の続編を置ける。
  視聴者が本当に見たいのは「AIの本気の到達点」でもある（他チャンネルで要望→実際に伸びた実例）
- **新モデルが出たら、同じ題材で即検証**: 「新しいAIで同じお題をやったら」は
  それ自体が記録としての価値を持つ（時事ジャック。小規模チャンネルでも跳ねた実例）
- **ショートを毎回3本切り出す**: 縦のゲーム画面はショートと相性がいい。
  事故の瞬間・記録更新・飲み干し、を `video/scripts/shorts.mjs` で切る
- **コメント欄は設計するもの**: 固定コメントで3つを聞く。
  ①「あなたの思い出のガラケーゲーム」（懐かし層はコメント欄が同窓会になる）
  ②「次にAIに作らせたいもの」（リクエスト採用ループ）
  ③「あなたの最高記録」（遊べるURLがあるから成立する。うちの強み）
- **AIの返答・提案・言い訳は拾って字幕化する**: 視聴者はAIの人格に反応する。
  ただし**リポジトリの道具の名前は出さない**（§0）。出すのはAIとの会話のほう
- **バグ・珍挙動は資産**: 直す前に必ず素材として残す（[footage-notes/](./footage-notes/)）。
  上位コメントはバグの瞬間にタイムスタンプ付きで付く

## 8. この番組が絶対にやらないこと

- **中身より煽りが強いサムネ・タイトル**（1回で信用を失う）
- **できていないものを、できたように見せる編集**
- **他人の著作物を「引用のふり」で使う**（[safety-checklist.md](./safety-checklist.md)）
- **AIが確かめていないことを「確認しました」と言う**（[CLAUDE.md](../../CLAUDE.md) §AIには確かめられないこと）

この4つは、再生数と引き換えにしない。
